# Chapter 11. 오류는 실패가 아니라 단서다

> **이번 Chapter의 핵심은 오류를 없애는 것이 아닙니다.**  
> 오류가 생겼을 때 멈추거나 바로 AI에게 답을 묻지 않고, **단서를 읽고 원인을 추론하는 디버깅 습관**을 만드는 것이 목표입니다.

---

## 오류가 나오면 왜 갑자기 머리가 하얘질까요?

프로그램을 작성하다 보면 반드시 오류를 만납니다.

초보자에게 오류는 종종 이런 느낌을 줍니다.

```text
코드가 틀렸다.
→ 나는 잘못했다.
→ 어디서부터 봐야 할지 모르겠다.
→ 일단 AI에게 전체 코드를 붙여 넣는다.
```

하지만 개발자가 오류를 보는 방식은 다릅니다.

```text
예상과 다른 일이 생겼다.
→ 어디서 달라졌는지 찾는다.
→ 원인 후보를 세운다.
→ 하나만 수정한다.
→ 다시 확인한다.
```

즉 오류는 실패 선언이 아닙니다.

> **오류는 다음에 어디를 확인해야 하는지 알려주는 정보입니다.**

---

## 1. 자동차 경고등처럼 생각해 봅시다

자동차 계기판에 경고등이 켜졌다고 해서 자동차 전체가 끝났다는 뜻은 아닙니다.

경고등은 다음 행동을 알려주는 신호입니다.

```text
엔진 경고등
→ 엔진 관련 부분을 점검해 보자.

타이어 공기압 경고등
→ 타이어 압력을 확인해 보자.
```

프로그래밍 오류 메시지도 비슷합니다.

![오류 메시지는 점검 위치를 알려주는 신호](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter11/error-message-as-signal.jpg)

예를 들어 다음 메시지를 보겠습니다.

```text
KeyError: 'scroe'
```

이 메시지는 정답을 직접 말해 주지는 않습니다.

하지만 중요한 단서를 줍니다.

```text
Dictionary의 key와 관련된 문제다.
'scroe'라는 이름을 사용했다.
```

이제 확인 범위가 크게 줄어듭니다.

> **오류 메시지는 정답이 아니라 단서다.**

---

## 2. 디버깅은 무작정 고치는 일이 아닙니다

디버깅을 다음 순서로 반복해 봅시다.

```text
1. 예상 결과를 적는다.
2. 실제 결과를 확인한다.
3. 차이가 처음 발생한 위치를 찾는다.
4. 관련 변수 값을 확인한다.
5. 원인 가설을 하나 세운다.
6. 한 부분만 수정한다.
7. 다시 실행한다.
8. 예상과 같은지 검증한다.
```

![디버깅 반복 루프](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter11/debugging-loop.jpg)

이 과정에서 가장 중요한 규칙은 다음입니다.

> **한 번에 여러 군데를 고치지 않습니다.**

여러 곳을 동시에 바꾸면 결과가 고쳐져도 무엇이 원인이었는지 알기 어렵습니다.

좋은 디버깅은 다음과 같습니다.

```text
가설 하나
→ 수정 하나
→ 재실행
→ 검증
```

## 3. 먼저 세 종류의 오류를 구분합니다

모든 오류가 같은 모습으로 나타나지는 않습니다.

크게 다음 세 가지로 생각해 볼 수 있습니다.

![문법 오류 실행 오류 논리 오류 비교](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter11/error-types-compare.jpg)

### ① 문법 오류

Python 문법 자체가 맞지 않아 실행 전에 막히는 경우입니다.

예:

```python
if score >= 80
    print("합격")
```

`:`가 빠졌습니다.

이 경우 Python은 보통 오류가 발생한 위치 근처를 알려줍니다.

---

### ② 실행 오류

문법은 맞지만 실행하는 도중 문제가 발생합니다.

예:

```python
student = {"name": "민수", "score": 85}
print(student["scroe"])
```

실행하면:

```text
KeyError: 'scroe'
```

프로그램이 실행되다가 해당 줄에서 멈춥니다.

---

### ③ 논리 오류

가장 주의해야 하는 경우입니다.

코드는 정상 실행되지만 결과가 틀립니다.

예:

```python
score = 80

if score > 80:
    print("합격")
else:
    print("불합격")
```

프로그램은 정상 실행됩니다.

하지만 요구사항이 `80점 이상이면 합격`이었다면 결과는 잘못되었습니다.

```text
요구사항: 80 이상
코드:     80 초과
```

이 경우 오류 메시지가 없습니다.

그래서 **실행 전에 예상 결과를 적는 습관**이 중요합니다.

---

## 4. 첫 번째 실습 — key 이름 오타 찾기

다음 코드를 실행하기 전에 먼저 예상해 봅시다.

```python
student = {
    "name": "민수",
    "score": 85
}

print(student["scroe"])
```

우리가 원한 결과는:

```text
85
```

하지만 실행하면:

```text
KeyError: 'scroe'
```

이제 디버깅 루틴을 적용합니다.

### 1단계. 예상 결과

```text
85가 출력되어야 한다.
```

### 2단계. 실제 결과

```text
KeyError: 'scroe'
```

### 3단계. 오류 위치

```python
student["scroe"]
```

### 4단계. 관련 값 확인

Dictionary에는 어떤 key가 있습니까?

```python
print(student.keys())
```

결과:

```text
dict_keys(['name', 'score'])
```

### 5단계. 가설

```text
scroe가 아니라 score를 사용해야 하는 것 같다.
```

### 6단계. 한 부분만 수정

```python
print(student["score"])
```

### 7단계. 다시 실행

```text
85
```

### 8단계. 검증

예상 결과와 같습니다.

이것이 디버깅입니다.

## 5. 두 번째 실습 — 숫자인 줄 알았는데 문자열이었다

다음 데이터를 보겠습니다.

```python
student = {
    "name": "민수",
    "score": "85"
}

if student["score"] >= 80:
    print("합격")
```

우리는 `85 >= 80`을 생각했습니다.

하지만 실제 `score`는 숫자 85가 아니라 문자열 `"85"`입니다.

실행하면 자료형 관련 오류가 발생합니다.

여기서 질문합니다.

```text
내가 예상한 자료형은 무엇인가?
실제 자료형은 무엇인가?
```

확인:

```python
print(student["score"])
print(type(student["score"]))
```

결과:

```text
85
<class 'str'>
```

화면에는 똑같이 `85`처럼 보였지만 실제 자료형은 다릅니다.

가설:

```text
문자열을 숫자와 비교해서 문제가 발생한 것 같다.
```

수정:

```python
student = {
    "name": "민수",
    "score": 85
}
```

또는 입력 데이터가 문자열이어야 하는 상황이라면 필요한 시점에 숫자로 변환할 수 있습니다.

핵심은 변환 문법을 외우는 것이 아니라:

> **예상한 자료형과 실제 자료형이 같은지 확인하는 것**입니다.

## 6. 세 번째 실습 — 실행은 되는데 경계값이 틀렸다

요구사항은 다음과 같습니다.

```text
80점 이상이면 합격
```

코드는 다음과 같습니다.

```python
score = 80

if score > 80:
    result = "합격"
else:
    result = "불합격"

print(result)
```

실행 결과:

```text
불합격
```

오류 메시지는 없습니다.

하지만 예상 결과는 `합격`입니다.

이럴 때는 Chapter 03에서 배운 **경계값**을 다시 확인합니다.

```text
79 → 불합격
80 → 합격
81 → 합격
```

조건을 확인합니다.

```python
score > 80
```

이 조건에서는 80이 포함되지 않습니다.

가설:

```text
경계 연산자가 잘못된 것 같다.
```

수정:

```python
if score >= 80:
```

논리 오류에서는 특히 다음 질문이 중요합니다.

> **결과가 바뀌는 경계값에서 테스트했는가?**

---

## 7. 네 번째 실습 — 들여쓰기 때문에 반복 결과가 달라졌다

다음 학생 목록이 있습니다.

```python
students = [
    {"name": "민수", "score": 85},
    {"name": "지영", "score": 72},
    {"name": "현우", "score": 91}
]
```

우리는 모든 학생의 이름과 점수를 출력하고 싶습니다.

그런데 다음처럼 작성했다고 해봅시다.

```python
for student in students:
    name = student["name"]
    score = student["score"]

print(name, score)
```

실행 결과:

```text
현우 91
```

오류 메시지는 없습니다.

하지만 예상은 세 줄입니다.

```text
민수 85
지영 72
현우 91
```

이때 질문합니다.

```text
반복해야 하는 일은 무엇인가?
print가 반복문 안에 있는가 밖에 있는가?
```

수정:

```python
for student in students:
    name = student["name"]
    score = student["score"]
    print(name, score)
```

들여쓰기는 단순한 모양이 아니라 **어떤 코드가 반복되고 어떤 코드가 반복 밖에서 실행되는지 결정하는 구조**입니다.

## 8. 다섯 번째 실습 — 함수에서 return을 빼먹었다

Chapter 10에서 다음 함수를 만들었습니다.

```python
def get_result(score):
    if score >= 80:
        result = "합격"
    else:
        result = "불합격"
```

그리고 다음과 같이 호출합니다.

```python
result = get_result(85)
print(result)
```

예상:

```text
합격
```

실제:

```text
None
```

함수 자체는 실행되었습니다.

하지만 결과를 밖으로 전달하지 않았습니다.

관련 질문:

```text
함수 안에서는 어떤 값이 만들어졌는가?
그 값을 호출한 곳으로 전달했는가?
```

가설:

```text
result를 만들었지만 return하지 않은 것 같다.
```

수정:

```python
def get_result(score):
    if score >= 80:
        result = "합격"
    else:
        result = "불합격"

    return result
```

다시 실행하면:

```text
합격
```

이 오류는 Chapter 10의 데이터 흐름 관점으로 보면 쉽게 이해할 수 있습니다.

```text
입력은 들어갔다.
처리도 되었다.
하지만 출력값이 다음 단계로 전달되지 않았다.
```

## 9. 여섯 번째 실습 — 값이 어디서부터 틀렸는지 찾기

다음 코드는 합격 학생 수를 세려고 합니다.

```python
students = [
    {"name": "민수", "score": 85},
    {"name": "지영", "score": 72},
    {"name": "현우", "score": 91}
]

passed_count = 0

for student in students:
    if student["score"] >= 80:
        passed_count = 1

print(passed_count)
```

예상:

```text
2
```

실제:

```text
1
```

프로그램은 정상 실행됩니다.

이럴 때 반복마다 변수 값을 직접 확인해 볼 수 있습니다.

```python
passed_count = 0

for student in students:
    print("처리 전:", student["name"], passed_count)

    if student["score"] >= 80:
        passed_count = 1

    print("처리 후:", student["name"], passed_count)
```

이 출력은 정답을 주는 것이 아니라 **값이 변하는 과정을 보여주는 단서**입니다.

문제는:

```python
passed_count = 1
```

입니다.

우리가 원한 것은 현재 값에 1을 더하는 것입니다.

```python
passed_count = passed_count + 1
```

또는:

```python
passed_count += 1
```

여기서 중요한 것은 수정 문법보다 다음 질문입니다.

> **이 변수는 매 반복마다 어떤 값으로 변해야 하는가?**

## 10. 디버깅할 때 print를 임시 센서처럼 사용합니다

코드가 길어지면 변수 값이 머릿속 예상과 실제로 같은지 확인하기 어렵습니다.

이때 `print()`를 임시 센서처럼 사용할 수 있습니다.

예:

```python
for student in students:
    score = student["score"]
    print("현재 학생:", student["name"])
    print("현재 score:", score)

    if score >= 80:
        print("조건 통과")
```

확인이 끝난 뒤 필요 없는 디버깅 출력은 제거하면 됩니다.

좋은 디버깅 출력은 목적이 분명합니다.

```text
현재 어떤 데이터를 처리 중인가?
현재 변수 값은 무엇인가?
조건 결과는 True인가 False인가?
함수가 무엇을 return했는가?
```

무작정 많은 값을 출력하는 것이 아니라 **가설을 확인하는 데 필요한 값만 출력**합니다.

## 11. 오류 메시지를 읽을 때 최소한 이것부터 봅니다

처음부터 오류 메시지 전체를 이해할 필요는 없습니다.

먼저 다음 네 가지를 찾아보세요.

```text
1. 오류 종류는 무엇인가?
2. 어느 파일/줄 근처인가?
3. 그 줄에서 어떤 값이나 이름을 사용했는가?
4. 마지막 오류 메시지가 무엇을 말하는가?
```

예를 들어:

```text
KeyError: 'score'
```

이라면:

```text
Dictionary key 문제인가?
정말 score라는 key가 존재하는가?
대소문자나 오타는 없는가?
현재 student 변수에 어떤 값이 들어 있는가?
```

처럼 범위를 좁힙니다.

## 12. 공식 문서는 언제 사용할까요?

스스로 원인을 생각했지만 Python의 정확한 동작을 모르겠다면 공식 문서를 사용할 수 있습니다.

예를 들어:

```text
Dictionary에서 존재하지 않는 key를 읽으면 어떤 오류가 발생하는가?
return이 없는 함수는 어떤 값을 반환하는가?
type()은 어떤 정보를 보여주는가?
```

이런 질문은 공식 문서로 확인하기 좋습니다.

순서는 다음을 권장합니다.

```text
내 예상 정리
→ 실제 결과 확인
→ 원인 가설
→ 필요한 경우 Python 공식 문서 확인
→ 수정
→ 다시 실행
→ 마지막에 AI로 검증
```

AI를 가장 먼저 사용하면 코드는 빨리 고쳐질 수 있습니다.

하지만 **왜 고쳐졌는지 설명하는 능력**은 자라지 않을 수 있습니다.

---

## 13. AI는 디버깅의 마지막 검증자로 사용합니다

스스로 디버깅한 뒤 AI에게 다음처럼 물어보는 것은 좋습니다.

```text
내 예상 결과는 2였습니다.
실제 결과는 1이었습니다.
반복문 안에서 passed_count = 1로 다시 대입되는 것이 원인이라고 판단했고,
passed_count += 1로 수정했습니다.

내 원인 분석이 맞는지 검토해 주세요.
```

이 방식에서는 AI가 생각을 대신하지 않습니다.

AI는 **내 가설을 검토하는 리뷰어**가 됩니다.

피해야 할 방식:

```text
이 코드 왜 안돼? 고쳐줘.
```

권장 방식:

```text
내 예상은 무엇이었고,
실제 결과는 무엇이었으며,
어디가 원인이라고 생각했고,
어떻게 수정했는지
먼저 설명한 뒤 검토를 요청합니다.
```

## 14. 직접 디버깅해 봅시다

아래 문제는 정답 코드를 바로 보지 말고 디버깅 루틴을 적용하세요.

### 실습 1. key 오류

```python
student = {
    "name": "지영",
    "score": 72
}

print(student["scores"])
```

적을 것:

```text
예상 결과:
실제 결과:
오류 종류:
문제가 발생한 위치:
내 가설:
수정한 한 부분:
재실행 결과:
```

---

### 실습 2. 경계값 오류

요구사항:

```text
90점 이상이면 A
80점 이상이면 B
나머지는 C
```

코드:

```python
score = 90

if score > 90:
    grade = "A"
elif score >= 80:
    grade = "B"
else:
    grade = "C"

print(grade)
```

특히 `89 / 90 / 91`을 테스트해 보세요.

---

### 실습 3. 누적 오류

```python
scores = [85, 72, 91]

total = 0

for score in scores:
    total = score

print(total)
```

예상 합계는 무엇인지 먼저 적으세요.

그리고 반복마다 `total`이 어떻게 변하는지 손으로 추적하세요.

---

### 실습 4. return 오류

```python
def get_grade(score):
    if score >= 90:
        grade = "A"
    elif score >= 80:
        grade = "B"
    else:
        grade = "C"


grade = get_grade(85)
print(grade)
```

함수 안에서 만들어진 값과 함수 밖에서 받은 값을 비교하세요.

## 16. 디버깅 기록을 남기면 실력이 더 빨리 늘어납니다

```text

민수와 현우가 합격이므로 2여야 했다.

원인
passed_count = 1로 매번 같은 값을 대입했다.

수정
passed_count += 1

카운터는 현재 값에 누적해야 한다.
```
