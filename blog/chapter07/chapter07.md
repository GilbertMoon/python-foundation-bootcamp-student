# Chapter 07. 현실의 데이터를 Python 구조로 표현하기

> **이번 Chapter의 핵심은 List와 Dictionary 문법을 다시 외우는 것이 아닙니다.**  
> 현실에 있는 사람, 상품, 주문 같은 대상을 프로그램 안에서 **어떤 데이터 구조로 표현할 것인지 설계하는 사고**를 익히는 것이 목표입니다.

---

## 현실의 대상을 코드로 옮길 때 가장 먼저 생각할 것

지금까지 우리는 학생 데이터를 계속 사용해 왔습니다.

처음에는 이름과 점수만 있었습니다.

```python
{"name": "민수", "score": 85}
```

그런데 실제 학생 정보에는 더 많은 속성이 있을 수 있습니다.

- 이름
- 점수
- 전공
- 출석률

예를 들어 민수의 정보를 다음처럼 표현할 수 있습니다.

```python
{
    "name": "민수",
    "score": 85,
    "major": "AI",
    "attendance": 92
}
```

여기서 중요한 질문은 이것입니다.

> **왜 이런 구조를 사용했을까요?**

`Dictionary`라는 문법을 배웠기 때문이 아닙니다.

학생 한 명이 여러 개의 **이름 있는 속성**을 가지고 있기 때문입니다.

---

## 1. 현실의 한 대상에는 여러 속성이 있습니다

민수라는 학생 한 명을 생각해 봅시다.

사람에게는 다음 정보가 자연스럽게 연결되어 있습니다.

```text
이름: 민수
점수: 85
전공: AI
출석률: 92
```

Python에서는 이런 구조를 Dictionary로 표현하기 좋습니다.

```python
student = {
    "name": "민수",
    "score": 85,
    "major": "AI",
    "attendance": 92
}
```

![현실 학생 카드에서 Dictionary로](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter07/student-card-to-dictionary.jpg)

이 구조를 사람의 말로 읽으면 다음과 같습니다.

```text
학생 한 명에게
name이라는 속성이 있고 값은 민수
score라는 속성이 있고 값은 85
major라는 속성이 있고 값은 AI
attendance라는 속성이 있고 값은 92
```

즉 Dictionary에서 중요한 것은 단순히 `{}`가 아닙니다.

> **값마다 이름을 붙여 현실의 속성을 표현할 수 있다는 것**이 중요합니다.

---

## 2. 왜 값의 위치만으로 관리하면 불편할까요?

다음과 같이 List만 사용해 학생 한 명을 표현할 수도 있습니다.

```python
student = ["민수", 85, "AI", 92]
```

코드는 짧아 보입니다.

하지만 다음 질문에 바로 답할 수 있을까요?

```python
student[2]
```

`2`가 무엇을 의미하는지 기억해야 합니다.

```text
0 → 이름
1 → 점수
2 → 전공
3 → 출석률
```

속성이 많아질수록 이 방식은 읽기 어려워집니다.

반면 Dictionary에서는:

```python
student["major"]
```

코드만 봐도 무엇을 가져오는지 알 수 있습니다.

따라서 현실 데이터를 표현할 때 다음 질문이 중요합니다.

> **이 값의 의미를 위치만으로 알 수 있는가, 아니면 속성 이름이 필요한가?**

학생처럼 여러 속성을 가진 대상은 보통 이름 있는 구조가 훨씬 이해하기 쉽습니다.

---

## 3. Dictionary의 key와 value를 현실의 속성으로 읽어 봅시다

다음 코드를 문법으로만 보지 마세요.

```python
student = {
    "name": "민수",
    "score": 85,
    "major": "AI",
    "attendance": 92
}
```

여기서:

```text
name       → 속성 이름(key)
민수       → 속성 값(value)

score      → 속성 이름(key)
85         → 속성 값(value)

major      → 속성 이름(key)
AI         → 속성 값(value)

attendance → 속성 이름(key)
92         → 속성 값(value)
```

즉 Dictionary를 설계한다는 것은 사실 다음 질문에 답하는 것입니다.

> **이 현실의 대상은 어떤 속성을 가져야 하는가?**

## 4. 학생이 여러 명이라면 어떻게 표현할까요?

학생 한 명은 Dictionary로 표현했습니다.

그런데 학생이 세 명이라면 어떻게 해야 할까요?

각 학생은 같은 종류의 속성을 가지고 있습니다.

```python
student1 = {
    "name": "민수",
    "score": 85,
    "major": "AI",
    "attendance": 92
}

student2 = {
    "name": "지영",
    "score": 72,
    "major": "Design",
    "attendance": 88
}

student3 = {
    "name": "현우",
    "score": 91,
    "major": "Data",
    "attendance": 97
}
```

이 세 개를 하나의 목록으로 묶으면 다음과 같습니다.

```python
students = [
    {"name": "민수", "score": 85, "major": "AI", "attendance": 92},
    {"name": "지영", "score": 72, "major": "Design", "attendance": 88},
    {"name": "현우", "score": 91, "major": "Data", "attendance": 97}
]
```

![여러 학생을 List of Dictionaries로 표현하기](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter07/students-list-of-dictionaries.jpg)

이 구조를 한 문장으로 설명하면 다음과 같습니다.

> **학생 한 명은 Dictionary, 여러 학생은 List of Dictionaries**

이 문장을 외우는 것이 목적은 아닙니다.

중요한 것은 왜 이런 구조가 자연스러운지 이해하는 것입니다.

```text
학생 한 명 = 하나의 대상
학생 여러 명 = 같은 종류의 대상 여러 개
```

## 5. `students[0]["score"]`를 단계별로 읽어 봅시다

초보자가 List와 Dictionary를 함께 사용할 때 자주 혼란스러워하는 코드가 있습니다.

```python
students[0]["score"]
```

한 번에 읽지 말고 두 단계로 나눠 봅시다.

### 첫 번째 단계

```python
students[0]
```

학생 목록에서 첫 번째 학생을 선택합니다.

결과:

```python
{"name": "민수", "score": 85, "major": "AI", "attendance": 92}
```

### 두 번째 단계

```python
students[0]["score"]
```

선택한 첫 번째 학생의 `score` 속성을 선택합니다.

결과:

```text
85
```

따라서 이렇게 읽으면 됩니다.

```text
students[0]           → 첫 번째 학생 선택
students[0]["score"] → 첫 번째 학생의 점수 선택
```

여기서 교수자가 자주 물어볼 수 있는 질문은 다음입니다.

> `0`은 무엇을 선택하는가?  
> `"score"`는 무엇을 선택하는가?

답은 각각 **대상 하나**와 **그 대상의 속성 하나**입니다.

## 6. 데이터 구조가 달라지면 문제 해결 방식도 달라집니다

예를 들어 학생 이름만 따로 List에 저장하고 점수도 따로 저장한다고 해봅시다.

```python
names = ["민수", "지영", "현우"]
scores = [85, 72, 91]
```

처음에는 간단해 보입니다.

하지만 학생별 전공과 출석률까지 추가하면:

```python
names = ["민수", "지영", "현우"]
scores = [85, 72, 91]
majors = ["AI", "Design", "Data"]
attendance = [92, 88, 97]
```

이제 같은 위치의 값들이 같은 학생이라는 사실을 계속 맞춰야 합니다.

```text
names[0]
scores[0]
majors[0]
attendance[0]
```

이 네 값이 모두 민수의 정보입니다.

하지만 데이터가 추가되거나 순서가 바뀌면 관리가 어려워질 수 있습니다.

반면 List of Dictionaries에서는 한 학생의 정보가 하나로 묶여 있습니다.

```python
students[0]
```

이 값 하나만 보면 민수의 모든 속성을 확인할 수 있습니다.

따라서 데이터 구조를 선택할 때는 문법보다 다음을 생각해야 합니다.

> **같이 움직여야 하는 데이터는 무엇인가?**

## 7. 새로운 속성을 추가해 봅시다

학생 정보에 `email`을 추가한다고 해봅시다.

기존 구조:

```python
{
    "name": "민수",
    "score": 85,
    "major": "AI",
    "attendance": 92
}
```

새 구조:

```python
{
    "name": "민수",
    "score": 85,
    "major": "AI",
    "attendance": 92,
    "email": "minsu@example.com"
}
```

여기서 중요한 점은 학생이라는 대상의 구조가 확장되었다는 것입니다.

학생 여러 명이 같은 구조를 사용한다면 다른 학생에게도 같은 속성을 추가하는 것이 자연스럽습니다.

이렇게 생각하면 현실의 요구사항 변화와 프로그램의 데이터 구조 변화가 연결됩니다.

## 8. 데이터를 설계한 뒤 반복과 조건을 적용합니다

데이터 구조를 먼저 잘 만들면 이전 Chapter에서 배운 반복과 조건을 그대로 사용할 수 있습니다.

예를 들어 출석률이 90 이상인 학생의 이름만 출력해 봅시다.

```python
students = [
    {"name": "민수", "score": 85, "major": "AI", "attendance": 92},
    {"name": "지영", "score": 72, "major": "Design", "attendance": 88},
    {"name": "현우", "score": 91, "major": "Data", "attendance": 97}
]

for student in students:
    if student["attendance"] >= 90:
        print(student["name"])
```

예상 결과:

```text
민수
현우
```

여기에는 우리가 지금까지 배운 사고가 모두 들어 있습니다.

```text
List                 → 여러 학생
Dictionary           → 학생 한 명의 속성
for                   → 학생 한 명씩 확인
student["attendance"] → 현재 학생의 출석률
if                    → 기준 판단
print                 → 필요한 결과 출력
```

즉 데이터 구조는 다른 문법과 분리된 주제가 아닙니다.

**문제를 해결할 수 있게 만드는 바탕**입니다.

## 9. 학생 데이터와 표는 사실 매우 비슷합니다

다음 데이터를 다시 보겠습니다.

```python
students = [
    {"name": "민수", "score": 85, "major": "AI", "attendance": 92},
    {"name": "지영", "score": 72, "major": "Design", "attendance": 88},
    {"name": "현우", "score": 91, "major": "Data", "attendance": 97}
]
```

이 데이터를 표로 바꾸면 다음과 같이 생각할 수 있습니다.

| name | score | major | attendance |
|---|---:|---|---:|
| 민수 | 85 | AI | 92 |
| 지영 | 72 | Design | 88 |
| 현우 | 91 | Data | 97 |

![Dictionary 구조와 데이터베이스 Table 연결](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter07/dictionary-to-table.jpg)

관계를 단순하게 보면 다음과 같습니다.

```text
학생 한 명의 Dictionary  → 한 행(row)
Dictionary의 key         → 열(column)의 이름
학생 여러 명의 List      → 여러 행으로 이루어진 table
```

이 연결은 앞으로 데이터베이스와 데이터 분석을 배울 때 매우 중요합니다.

지금 배우는 Python 자료구조와 전혀 별개의 세계가 아닙니다.

## 10. 데이터베이스와 연결해 미리 생각해 봅시다

Python에서는 다음처럼 사용합니다.

```python
student["score"]
```

이것은 현재 학생의 점수라는 속성을 선택하는 것입니다.

데이터베이스에서도 비슷한 질문을 하게 됩니다.

```text
학생 테이블에서 score 열을 보고 싶다.
```

또 Python에서:

```python
for student in students:
```

이라고 여러 학생을 확인했다면, 데이터베이스에서는 여러 row를 대상으로 조건을 적용하게 됩니다.

Chapter 05에서 이미 보았던:

```python
for student in students:
    if student["score"] >= 80:
```

이라는 사고는 나중에 SQL의 다음 질문과 연결됩니다.

```text
score가 80 이상인 행만 찾는다.
```

따라서 지금 배우는 핵심은 Python 문법 하나가 아니라 **데이터를 바라보는 방법**입니다.

## 13. 초보자가 자주 하는 실수

### 실수 1. 데이터 구조보다 코드부터 작성한다

먼저 현실의 대상과 속성을 정리하세요.

### 실수 2. Dictionary key 이름을 일관되지 않게 사용한다

예를 들어:

```python
{"name": "민수", "score": 85}
{"student_name": "지영", "score": 72}
```

같은 종류의 데이터라면 가능하면 같은 구조를 유지하는 것이 좋습니다.

### 실수 3. 값의 의미를 위치에만 의존한다

```python
["민수", 85, "AI", 92]
```

구조가 복잡해질수록 의미를 파악하기 어려워집니다.

### 실수 4. List 전체와 현재 Dictionary 하나를 혼동한다

```text
students → 학생 전체 목록
student  → 현재 학생 한 명
```

### 실수 5. 새로운 속성을 추가한 뒤 코드의 영향 범위를 확인하지 않는다

데이터 구조가 바뀌면 그 데이터를 사용하는 코드도 함께 살펴봐야 합니다.

## 14. AI를 사용하기 전에 먼저 구조를 직접 설계하세요

AI에게 바로 이렇게 묻지 마세요.

```text
이 문제 Python으로 풀어줘.
```

먼저 스스로 적어 봅니다.

```text
현실의 대상:

대상 한 개의 속성:

대상 한 개를 표현할 구조:

대상이 여러 개일 때 구조:

필요한 조건:

최종 결과:
```

그다음 직접 Python으로 옮기고 실행합니다.

AI는 마지막에 다음과 같은 용도로 사용할 수 있습니다.

```text
내가 설계한 데이터 구조가 요구사항을 잘 표현하는지 설명해 줘.
```

또는:

```text
이 구조의 장점과 개선할 점을 알려줘.
```

핵심은 **AI에게 데이터 설계 사고 자체를 넘기지 않는 것**입니다.
