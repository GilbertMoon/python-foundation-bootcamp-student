# Chapter 02. 문제를 실행 가능한 작은 단계로 나누기

> **이번 Chapter의 핵심은 “무엇부터 해야 할지 모르겠다”를 해결하는 것입니다.**  
> 큰 문제를 한 번에 해결하려 하지 않고, 컴퓨터가 순서대로 따라갈 수 있는 **작은 단계**로 나누는 연습을 합니다.

---

## 문제를 보면 왜 머리가 하얘질까요?

Python 문법을 배운 뒤에도 문제를 보면 손이 멈추는 경우가 많습니다.

예를 들어 다음 요구사항을 보겠습니다.

> 학생들의 이름과 점수를 확인하고, 80점 이상이면 합격, 그렇지 않으면 불합격으로 표시한 뒤 모든 학생의 결과를 출력하세요.

문장만 보면 어렵지 않아 보입니다.

그런데 막상 빈 편집기를 열면 이런 생각이 들 수 있습니다.

- 어디부터 작성하지?
- `for`부터 써야 하나?
- `if`부터 써야 하나?
- 점수를 먼저 꺼내야 하나?
- 출력은 어디에 넣지?

이때 문제는 Python 문법을 몰라서가 아닐 수 있습니다.

**해야 할 일을 아직 순서대로 정리하지 않았기 때문입니다.**

이번 Chapter에서는 이 습관을 바꿉니다.

> **코드를 쓰기 전에, 사람이 해결하는 순서를 먼저 적습니다.**

---

## 1. 큰 문제는 작은 단계로 나눌 수 있습니다

0강부터 계속 사용한 학생 성적 문제를 다시 보겠습니다.

```python
students = [
    {"name": "민수", "score": 85},
    {"name": "지영", "score": 72},
    {"name": "현우", "score": 91}
]
```

우리가 해야 할 일은 다음과 같습니다.

> 각 학생의 점수를 확인하고 80점 이상이면 합격, 그렇지 않으면 불합격을 출력한다.

이 문장을 한 번에 코드로 바꾸려고 하지 마세요.

먼저 작은 행동으로 나눕니다.

1. 학생 데이터를 준비한다.
2. 학생을 한 명 선택한다.
3. 선택한 학생의 이름을 확인한다.
4. 선택한 학생의 점수를 확인한다.
5. 점수가 80점 이상인지 판단한다.
6. 합격 또는 불합격 결과를 만든다.
7. 이름, 점수, 결과를 출력한다.
8. 다음 학생에게 같은 작업을 반복한다.

![큰 문제를 작은 단계로 나누기](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter02/problem-step-breakdown.jpg)

이렇게 나누면 갑자기 문제가 훨씬 단순해집니다.

우리가 해야 하는 일은 거대한 하나의 작업이 아니라, **작은 작업 여러 개를 올바른 순서로 연결하는 것**입니다.

---

## 2. 프로그래밍은 “순서가 있는 절차”입니다

컴퓨터는 사람처럼 문맥을 알아서 해석하지 않습니다.

사람에게는 이렇게 말해도 충분할 수 있습니다.

> 학생들 점수 보고 합격 여부 출력해 줘.

하지만 컴퓨터에게는 너무 많은 내용이 생략되어 있습니다.

컴퓨터가 실제로 실행하려면 더 구체적인 순서가 필요합니다.

```text
학생 목록을 준비한다
        ↓
학생 한 명을 선택한다
        ↓
그 학생의 점수를 확인한다
        ↓
점수가 80점 이상인지 판단한다
        ↓
합격 또는 불합격 결과를 만든다
        ↓
결과를 출력한다
        ↓
다음 학생으로 이동한다
```

이 순서를 만드는 것이 프로그래밍에서 매우 중요합니다.

> **프로그램은 컴퓨터가 따라갈 수 있을 만큼 구체적으로 정리된 절차입니다.**

---

## 3. 아직 코드를 쓰지 말고 한국어로 먼저 적어 봅시다

이번에는 코드를 숨기고 문제만 봅니다.

### 문제

학생 데이터가 다음과 같이 주어졌습니다.

```text
민수 85점
지영 72점
현우 91점
```

80점 이상이면 합격, 그렇지 않으면 불합격이라고 출력하려고 합니다.

이때 바로 Python을 작성하지 않습니다.

먼저 종이나 메모장에 다음처럼 적습니다.

```text
1. 학생 목록을 준비한다.
2. 학생을 한 명씩 확인한다.
3. 이름을 가져온다.
4. 점수를 가져온다.
5. 점수가 80점 이상인지 확인한다.
6. 맞으면 합격, 아니면 불합격으로 정한다.
7. 이름, 점수, 결과를 출력한다.
```

이것만 작성할 수 있어도 문제의 절반은 해결된 것입니다.

왜냐하면 이제 남은 일은 **이 절차를 Python 문법으로 번역하는 것**이기 때문입니다.

---

## 4. 한국어 절차를 Python 코드로 옮겨 봅시다

먼저 한국어로 생각한 절차를 하나씩 Python과 연결해 보겠습니다.

### 단계 1. 학생 목록을 준비한다

한국어:

```text
학생 여러 명의 데이터를 준비한다.
```

Python:

```python
students = [
    {"name": "민수", "score": 85},
    {"name": "지영", "score": 72},
    {"name": "현우", "score": 91}
]
```

---

### 단계 2. 학생을 한 명씩 확인한다

한국어:

```text
학생 목록에서 한 명씩 꺼낸다.
```

Python:

```python
for student in students:
```

---

### 단계 3. 이름과 점수를 가져온다

한국어:

```text
현재 학생의 이름과 점수를 확인한다.
```

Python:

```python
name = student["name"]
score = student["score"]
```

---

### 단계 4. 80점 이상인지 판단한다

한국어:

```text
점수가 80점 이상인지 확인한다.
```

Python:

```python
if score >= 80:
```

---

### 단계 5. 결과를 만든다

한국어:

```text
80점 이상이면 합격, 아니면 불합격으로 정한다.
```

Python:

```python
if score >= 80:
    result = "합격"
else:
    result = "불합격"
```

---

### 단계 6. 결과를 출력한다

한국어:

```text
이름, 점수, 결과를 보여준다.
```

Python:

```python
print(name, score, result)
```

![한국어 절차와 Python 코드 대응](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter02/procedure-to-code.jpg)

여기서 중요한 점이 하나 있습니다.

> **Python 코드는 갑자기 머릿속에서 만들어지는 것이 아닙니다.**  
> 먼저 문제를 절차로 정리하고, 그 절차를 Python 문법으로 바꾸는 것입니다.

## 5. 전체 코드를 다시 보면 훨씬 단순하게 보입니다

이제 전체 코드를 보겠습니다.

```python
students = [
    {"name": "민수", "score": 85},
    {"name": "지영", "score": 72},
    {"name": "현우", "score": 91}
]

for student in students:
    name = student["name"]
    score = student["score"]

    if score >= 80:
        result = "합격"
    else:
        result = "불합격"

    print(name, score, result)
```

이제 이 코드를 문법 이름으로만 보지 마세요.

```text
데이터 준비
   ↓
한 명 선택
   ↓
필요한 값 확인
   ↓
조건 판단
   ↓
결과 생성
   ↓
출력
```

코드는 이 순서를 표현한 것입니다.

## 6. 순서를 바꾸면 왜 문제가 생길까요?

프로그래밍에서는 **무엇을 하는가**만큼 **언제 하는가**도 중요합니다.

예를 들어 다음 순서를 보겠습니다.

```text
1. 합격인지 판단한다.
2. 학생의 점수를 확인한다.
```

이 순서는 이상합니다.

왜냐하면 점수를 아직 모르는데 먼저 합격 여부를 판단하려고 하기 때문입니다.

올바른 순서는 다음과 같습니다.

```text
1. 학생의 점수를 확인한다.
2. 그 점수가 80점 이상인지 판단한다.
```

Python에서도 마찬가지입니다.

다음 코드는 정상입니다.

```python
score = student["score"]

if score >= 80:
    result = "합격"
```

`score` 값을 먼저 준비한 뒤 그 값을 이용해서 판단합니다.

![순서가 중요한 이유](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter02/why-order-matters.jpg)

이 생각은 앞으로 함수, 파일 처리, 데이터 분석, 데이터베이스 작업에서도 계속 중요합니다.

> **뒤 단계가 앞 단계의 결과를 사용한다면 순서를 마음대로 바꿀 수 없습니다.**

---

## 7. 앞 단계와 뒤 단계의 관계를 찾아봅시다

각 단계는 따로 떨어져 있지 않습니다.

다음처럼 연결됩니다.

```text
학생을 선택한다
        ↓
선택한 학생이 있어야 이름과 점수를 확인할 수 있다
        ↓
점수가 있어야 합격 여부를 판단할 수 있다
        ↓
판단 결과가 있어야 결과를 출력할 수 있다
```

이 연결을 **의존 관계**라고 생각할 수 있습니다.

어려운 용어를 외울 필요는 없습니다.

그냥 다음 질문을 하면 됩니다.

> **이 단계를 실행하려면 그 전에 무엇이 준비되어 있어야 하지?**

예를 들어:

- 점수를 판단하려면 → 점수가 먼저 있어야 한다.
- 평균을 계산하려면 → 여러 점수가 먼저 있어야 한다.
- 결과를 출력하려면 → 출력할 결과가 먼저 만들어져야 한다.

이 질문 하나만 잘해도 코드의 순서를 훨씬 쉽게 정할 수 있습니다.

## 8. 의사코드(Pseudocode)를 사용해 봅시다

코드를 작성하기 전에 사람의 말과 코드 사이에 한 단계를 더 둘 수 있습니다.

바로 **의사코드(Pseudocode)**입니다.

의사코드는 실제 Python 문법이 아닙니다.

문제를 해결하는 절차를 코드처럼 정리한 메모라고 생각하면 됩니다.

예를 들어 학생 성적 문제를 다음처럼 적을 수 있습니다.

```text
학생 목록 준비

학생 목록의 각 학생에 대해 반복
    이름 확인
    점수 확인

    만약 점수가 80 이상이면
        결과 = 합격
    아니면
        결과 = 불합격

    이름, 점수, 결과 출력
```

이 정도면 충분합니다.

괄호, 콜론, 들여쓰기 문법이 정확하지 않아도 괜찮습니다.

이 단계에서는 **생각의 순서가 맞는지**가 더 중요합니다.

## 10. 이번에는 요구사항을 조금 확장해 봅시다

기존 문제에 한 가지 요구사항을 추가하겠습니다.

> 합격한 학생은 `축하합니다`, 불합격한 학생은 `다시 도전해 봅시다`라는 메시지도 함께 출력하세요.

코드부터 작성하지 않습니다.

먼저 절차를 수정합니다.

```text
1. 학생 목록을 준비한다.
2. 학생을 한 명씩 선택한다.
3. 이름과 점수를 확인한다.
4. 점수가 80점 이상인지 판단한다.
5. 합격이면 결과를 합격으로 정한다.
6. 합격이면 메시지를 "축하합니다"로 정한다.
7. 불합격이면 결과를 불합격으로 정한다.
8. 불합격이면 메시지를 "다시 도전해 봅시다"로 정한다.
9. 이름, 점수, 결과, 메시지를 출력한다.
```

그 다음 코드를 작성합니다.

```python
students = [
    {"name": "민수", "score": 85},
    {"name": "지영", "score": 72},
    {"name": "현우", "score": 91}
]

for student in students:
    name = student["name"]
    score = student["score"]

    if score >= 80:
        result = "합격"
        message = "축하합니다"
    else:
        result = "불합격"
        message = "다시 도전해 봅시다"

    print(name, score, result, message)
```

예상 결과:

```text
민수 85 합격 축하합니다
지영 72 불합격 다시 도전해 봅시다
현우 91 합격 축하합니다
```

요구사항이 늘어났지만 해결 방법은 같습니다.

> **요구사항이 추가되면 코드부터 고치는 것이 아니라, 먼저 절차에 어떤 단계가 추가되는지 찾습니다.**

## 11. 실행하기 전에 손으로 추적해 봅시다

민수 한 명만 대상으로 실행 과정을 따라가 보겠습니다.

```text
현재 학생 = 민수
        ↓
name = "민수"
        ↓
score = 85
        ↓
85 >= 80 ?
        ↓
True
        ↓
result = "합격"
message = "축하합니다"
        ↓
민수 85 합격 축하합니다 출력
```

이 연습을 **실행 추적**이라고 생각하면 됩니다.

코드를 실행하기 전에 변수 값이 어떻게 바뀌는지 손으로 따라가 보세요.

초보자에게 이 습관은 매우 중요합니다.

코드가 예상과 다르게 동작할 때도 어느 단계에서 값이 달라졌는지 찾기 쉬워집니다.

## 13. 직접 해보기 ② — 점수에 5점을 더한 뒤 판정하기

이번에는 순서가 더 중요합니다.

> 모든 학생의 원래 점수에 5점을 더한 뒤, 변경된 점수가 80점 이상이면 합격으로 판단하세요.

잘 생각해 보세요.

다음 중 어떤 순서가 맞을까요?

### A

```text
합격 판단
→ 5점 추가
→ 출력
```

### B

```text
점수 확인
→ 5점 추가
→ 변경된 점수로 합격 판단
→ 출력
```

정답은 B입니다.

왜냐하면 합격 여부가 **5점을 더한 후의 점수**에 따라 결정되기 때문입니다.

이번 실습에서는 코드보다 **순서의 이유를 설명하는 것**이 더 중요합니다.

## 14. 직접 해보기 ③ — 주문 문제도 단계로 나눠 봅시다

Chapter 01에서 사용한 주문 문제를 가져오겠습니다.

```python
orders = [
    {"customer": "민수", "amount": 45000},
    {"customer": "지영", "amount": 72000},
    {"customer": "현우", "amount": 53000}
]
```

요구사항:

> 주문 금액이 50,000원 이상이면 무료배송, 그렇지 않으면 배송비 3,000원이라고 출력하세요.

코드는 아직 작성하지 않습니다.

먼저 절차를 적어 보세요.

```text
1.
2.
3.
4.
5.
6.
```

생각할 질문:

- 여러 개인 것은 무엇인가?
- 무엇을 하나씩 확인해야 하는가?
- 판단 전에 어떤 값이 필요할까?
- 판단 기준은 무엇인가?
- 마지막에 무엇을 출력해야 할까?

학생 성적 문제와 구조가 매우 비슷하다는 점도 확인해 보세요.

---

## 15. 직접 해보기 ④ — 일부러 잘못된 순서를 찾아봅시다

다음 절차에서 잘못된 부분을 찾아보세요.

```text
1. 학생 목록을 준비한다.
2. 학생 한 명을 선택한다.
3. 합격 결과를 출력한다.
4. 점수를 확인한다.
5. 점수가 80점 이상인지 판단한다.
```

어디가 잘못되었나요?

`3. 합격 결과를 출력한다`가 너무 일찍 실행되고 있습니다.

아직 점수를 확인하지도 않았고 합격 여부를 판단하지도 않았습니다.

올바른 순서는 다음과 비슷해야 합니다.

```text
학생 선택
→ 점수 확인
→ 조건 판단
→ 결과 생성
→ 결과 출력
```

이처럼 **잘못된 순서를 찾아 수정하는 연습**도 문제 해결 훈련입니다.

## 16. 문제를 나눌 때 사용하는 6가지 질문

앞으로 문제가 나오면 다음 질문을 순서대로 사용해 보세요.

### 질문 1. 최종적으로 무엇을 만들어야 하나?

출력인지, 합계인지, 특정 데이터인지 먼저 확인합니다.

### 질문 2. 어떤 데이터가 필요한가?

이름, 점수, 주문 금액처럼 문제 해결에 필요한 값을 찾습니다.

### 질문 3. 여러 데이터 중 무엇을 하나씩 처리해야 하나?

반복이 필요한지 확인합니다.

### 질문 4. 어떤 판단이 필요한가?

`80점 이상`, `50,000원 이상` 같은 기준을 찾습니다.

### 질문 5. 판단 전에 반드시 준비되어야 하는 값은 무엇인가?

순서를 결정하는 핵심 질문입니다.

### 질문 6. 결과를 만들기까지 어떤 순서로 움직여야 하나?

마지막으로 전체 실행 흐름을 정리합니다.

이 질문을 반복하면 점점 문제를 보는 방식이 달라집니다.

## 17. 이번 Chapter의 수업 규칙

이번 Bootcamp의 핵심은 **스스로 생각하는 시간을 확보하는 것**입니다.

따라서 문제를 받으면 다음 순서로 진행합니다.

### 1단계 — 문제만 읽기

아직 코드를 작성하지 않습니다.

### 2단계 — 한국어 절차 작성

최소 4~6개의 단계로 나눕니다.

### 3단계 — 예상 결과 작성

실행 전에 결과를 생각합니다.

### 4단계 — Python 코드 작성

정리한 절차를 코드로 번역합니다.

### 5단계 — 실행 및 비교

예상 결과와 실제 결과가 같은지 확인합니다.

### 6단계 — 필요하면 공식 문서 확인

문법이 기억나지 않는다면 Python 공식 문서를 참고할 수 있습니다.

### 7단계 — 마지막에 AI로 검토

직접 생각하고 코드를 실행한 뒤에 AI를 사용합니다.

AI에게 처음부터 정답 코드를 요청하지 않습니다.

> **AI는 생각을 대신하는 도구가 아니라, 내가 생각한 내용을 검토하는 도구로 사용합니다.**

## 18. 초보자가 자주 하는 실수

### 실수 1. 요구사항을 읽자마자 코드부터 작성한다

문제의 전체 구조가 정리되지 않아 중간에 계속 수정하게 됩니다.

**해결:** 코드 전에 한국어 절차를 적습니다.

---

### 실수 2. 너무 큰 단위로 나눈다

예:

```text
1. 학생 성적을 처리한다.
2. 출력한다.
```

`학생 성적을 처리한다` 안에 너무 많은 작업이 들어 있습니다.

**해결:** 컴퓨터가 한 번에 수행할 수 있을 정도로 더 작게 나눕니다.

```text
학생 선택
→ 점수 확인
→ 조건 판단
→ 결과 생성
→ 출력
```

---

### 실수 3. 너무 세세하게만 나눈다

반대로 모든 기호와 문법까지 한국어 단계에 넣으면 오히려 복잡해집니다.

중요한 것은 **문제 해결에 의미 있는 행동 단위**입니다.

---

### 실수 4. 순서를 생각하지 않는다

필요한 값이 만들어지기 전에 그 값을 사용하려고 합니다.

**해결:** 매 단계마다 묻습니다.

> 이 단계를 실행하려면 앞에서 무엇이 준비되어 있어야 하지?

## 19. 오늘 반드시 기억할 한 문장

> **큰 문제를 한 번에 풀려고 하지 말고, 컴퓨터가 따라갈 수 있는 작은 순서로 나눈다.**

```text
문제 읽기

   ↓
순서 정하기
   ↓
의사코드 작성
   ↓
Python으로 번역
   ↓
실행 전 예상
   ↓
실행하여 확인
```
