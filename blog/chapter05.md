# Chapter 08·09·10 통합 실습 — 자연어 요구사항을 프로그램 구조로 바꾸기

> **이번 통합 실습의 목표는 Python 코드를 빨리 작성하는 것이 아닙니다.**  
> 이미 배운 Python 문법을 사용하기 전에, 실제 자연어 요구사항 속에서 **데이터 / 반복 / 조건 / 처리 / 결과**를 스스로 찾아내고, 이를 작은 기능과 데이터 흐름으로 바꾸는 연습을 합니다.

이번 강의에서는 다음 세 Chapter의 사고방식을 하나로 연결합니다.

- Chapter 08: 긴 요구사항을 작은 논리 블록으로 분해하기
- Chapter 09: 큰 문제를 작은 책임으로 나누고 함수 후보 찾기
- Chapter 10: 함수의 입력과 결과를 연결해 프로그램 흐름 만들기

최종 목표는 다음과 같습니다.

```text
자연어 요구사항
↓
데이터 / 반복 / 조건 / 처리 / 결과
↓
논리 블록
↓
책임 분리
↓
함수 후보
↓
입력 / 처리 / 결과
↓
데이터 흐름
↓
수도코드
↓
Python 코드
```

> **코드는 마지막 단계입니다.**  
> 코드를 쓰기 전에 문제의 구조를 말로 설명할 수 있어야 합니다.

# 0. 이 통합 실습이 해결하려는 문제

Python 문법을 알고 있어도 실제 요구사항을 받으면 다음과 같은 상황이 자주 생깁니다.

```text
for는 배웠는데 어디서 반복해야 하는지 모르겠다.
if는 배웠는데 어떤 조건을 코드로 옮겨야 하는지 모르겠다.
List와 Dictionary는 배웠는데 어떤 데이터를 어떻게 표현해야 하는지 모르겠다.
함수는 배웠는데 무엇을 함수로 나눠야 하는지 모르겠다.
return은 배웠는데 언제 필요한지 모르겠다.
```

이 문제는 문법 부족보다 **요구사항을 프로그램 구조로 번역하는 연습 부족**에서 생기는 경우가 많습니다.

따라서 이번 실습에서는 문제를 읽자마자 Python 문법을 찾지 않습니다.

다음 다섯 가지를 먼저 찾습니다.

```text
데이터
반복
조건
처리
결과
```

이 다섯 칸이 프로그램 설계의 출발점입니다.

---

# 1. 자연어 요구사항에서 다섯 가지를 찾는 방법

## 1-1. 데이터 — 무엇을 가지고 일하는가?

먼저 **명사**를 찾습니다.

예:

```text
학생
이름
점수
출석률
주문
회원 여부
주문 금액
프로젝트 점수
```

질문:

```text
무엇을 입력으로 가지고 있는가?
한 개의 항목은 어떤 속성을 가지는가?
여러 개의 항목은 어떤 자료구조로 표현할 수 있는가?
```

자연어에서 이런 표현이 보이면 데이터일 가능성이 높습니다.

```text
학생은 이름, 점수, 출석률을 가진다.
주문은 고객 이름, 금액, 회원 여부를 가진다.
각 상품에는 이름과 가격이 있다.
```

---

## 1-2. 반복 — 무엇이 여러 개이고, 무엇을 하나씩 처리하는가?

다음 표현을 찾습니다.

```text
모든
각각
한 명씩
하나씩
여러 명
여러 건
전체
모든 주문
모든 학생
```

이 표현들은 반복의 강한 신호입니다.

예:

> 모든 학생을 한 명씩 확인하세요.

이 문장을 읽으면 코드보다 먼저 다음 구조를 떠올립니다.

```text
여러 학생이 있다.
↓
현재 학생 한 명을 선택한다.
↓
그 학생에게 필요한 처리를 한다.
↓
다음 학생으로 이동한다.
```

질문:

```text
여러 개인 것은 무엇인가?
현재 처리 중인 한 개는 무엇인가?
같은 일을 몇 번 반복해야 하는가?
```

---

## 1-3. 조건 — 언제 결과가 달라지는가?

다음 표현을 찾습니다.

```text
이면
이상이면
미만이면
같으면
그리고
면서
또는
거나
그 외
그렇지 않으면
```

이 표현들은 조건의 신호입니다.

예:

> 점수가 90점 이상이고 출석률이 80% 이상이면 우수입니다.

다음처럼 해체합니다.

```text
조건 A: 점수 >= 90
조건 B: 출석률 >= 80
관계: AND
결과: 우수
```

또 다른 예:

> 점수가 70점 이상이거나 프로젝트 점수가 80점 이상이면 재검토입니다.

```text
조건 A: 점수 >= 70
조건 B: 프로젝트 점수 >= 80
관계: OR
결과: 재검토
```

질문:

```text
무엇을 판단하는가?
기준값은 무엇인가?
모두 만족해야 하는가?
하나만 만족해도 되는가?
조건이 서로 겹치는가?
겹친다면 어떤 조건이 먼저인가?
```

---

## 1-4. 처리 — 데이터를 가지고 무엇을 만드는가?

다음과 같은 **동사**를 찾습니다.

```text
분류한다
계산한다
더한다
누적한다
저장한다
만든다
변환한다
판단한다
요약한다
```

예:

> 각 학생의 상태를 판단한 뒤 새로운 Dictionary를 만들고 결과 List에 저장하세요.

처리는 다음처럼 나눌 수 있습니다.

```text
상태 판단
↓
새 Dictionary 생성
↓
결과 List에 저장
```

처리는 하나의 큰 덩어리일 수도 있고 여러 개의 작은 책임으로 나뉠 수도 있습니다.

---

## 1-5. 결과 — 마지막에 무엇이 남아야 하는가?

다음 표현을 찾습니다.

```text
출력하세요
저장하세요
반환하세요
목록을 만드세요
평균을 구하세요
요약 문장을 만드세요
```

결과는 크게 두 종류로 생각할 수 있습니다.

```text
사람에게 보여주는 결과
→ print

다음 코드가 다시 사용할 결과
→ 변수 저장 / return / List 저장
```

질문:

```text
이 결과는 화면에 보여주면 끝나는가?
아니면 다음 처리에서 다시 사용하는가?
반복이 끝난 뒤에도 남아 있어야 하는가?
```

# 2. 요구사항을 읽을 때 사용할 표시 방법

긴 문장을 처음부터 코드로 바꾸지 않습니다.

먼저 문장에 태그를 붙여 봅니다.

예:

> **모든 학생을 한 명씩 확인하세요. 점수가 90점 이상이고 출석률이 80% 이상이면 `우수`, 점수가 80점 이상이고 출석률이 80% 이상이면 `수료`, 그 외에는 `보완 필요`로 분류합니다. 각 학생의 이름과 상태를 출력하세요.**

다음처럼 표시합니다.

```text
[반복] 모든 학생을 한 명씩 확인한다.

[조건] 점수 >= 90 AND 출석률 >= 80
[처리/결과] → 우수로 분류

[조건] 점수 >= 80 AND 출석률 >= 80
[처리/결과] → 수료로 분류

[조건] 그 외
[처리/결과] → 보완 필요로 분류

[결과] 각 학생의 이름과 상태를 출력
```

그리고 문장에 직접 쓰이지 않았지만 필요한 데이터도 찾습니다.

```text
[데이터]
- 학생 목록
- 현재 학생
- 이름
- 점수
- 출석률
```

> **자연어 문장을 프로그램으로 바꾸는 첫 번째 기술은 문장을 분류해서 읽는 것입니다.**

# 3. 한 문장을 세 번 읽는 습관

긴 요구사항은 한 번에 이해하려고 하지 않습니다.

## 1회차 — 결과부터 찾기

```text
마지막에 무엇을 만들어야 하는가?
무엇을 출력하거나 저장해야 하는가?
```

## 2회차 — 반복과 조건 찾기

```text
무엇이 여러 개인가?
무엇을 하나씩 처리하는가?
언제 결과가 달라지는가?
```

## 3회차 — 처리와 데이터 흐름 찾기

```text
판단 뒤에 어떤 계산이나 저장이 필요한가?
앞 단계 결과를 다음 단계가 사용하는가?
```

이렇게 읽으면 긴 문장을 한 번에 코드로 번역하려는 부담이 줄어듭니다.



```text

↓
```

```text
↓
기능 C
↓

```

핵심:

> **함수가 여러 개 있다는 것이 중요한 것이 아니라, 값이 함수 사이에서 끊기지 않고 이동하는 것이 중요합니다.**

# 5. `print`와 `return`을 문제 요구사항에서 구분하기

```text
print
→ 사람에게 화면으로 보여준다.

return
→ 다음 코드가 다시 사용할 값을 전달한다.
```

예를 들어 상태 판단 기능이 `수료`라는 결과를 만들었다고 생각합니다.

요구사항이 다음과 같다면:

> 상태를 판단해 화면에 출력하세요.

상태가 여기서 끝날 수도 있습니다.

하지만 다음과 같다면:

> 상태를 판단한 뒤 그 상태를 이용해 처리 코드를 만드세요.

상태는 다음 단계에서 다시 필요합니다.

```text
상태 판단
↓
status
↓
처리 코드 판단
```

이때 상태 판단 기능이 결과를 `print`만 하고 끝내면 다음 기능에 전달할 값이 없습니다.

항상 묻습니다.

```text
이 값은 여기서 끝나는가?
아니면 다음 처리의 입력이 되는가?
```

# 6. 반복을 볼 때는 항상 세 구간으로 나눕니다

반복 문제를 만나면 다음 구조로 봅니다.

```text
반복 전
↓
반복 중
↓
반복 후
```

예를 들어 결과 List를 만드는 문제라면:

```text
반복 전
- 빈 결과 List 준비

반복 중
- 현재 학생 선택
- 상태 판단
- 새 결과 데이터 생성
- 결과 List에 저장

반복 후
- 완성된 결과 List 출력
```

평균을 계산한다면:

```text
반복 전
- 합계 준비

반복 중
- 현재 점수를 합계에 누적

반복 후
- 합계를 학생 수로 나누어 평균 계산
- 평균 출력
```

> **반복 안에서 해야 할 일과 반복이 끝난 뒤 해야 할 일을 구분하는 것이 중요합니다.**

# 19. Chapter 11 준비용 기준 코드

아래 코드는 이번 5개 실습의 정답이 아닙니다.

다음 시간 디버깅 연습에서 사용할 **정상 동작 기준 코드**입니다.

먼저 위 실습을 완료한 뒤 사용합니다.

복사해서 붙여 넣지 말고 직접 입력합니다.

```python
def get_result(score, attendance):
    if score >= 90 and attendance >= 80:
        return "우수"
    elif score >= 80 and attendance >= 80:
        return "수료"
    else:
        return "보완 필요"


def get_action(result):
    if result == "우수" or result == "수료":
        return "PASS"
    else:
        return "REVIEW"


def make_summary(name, score, attendance, result, action):
    return (
        f"{name} / 점수 {score} / 출석 {attendance}% / "
        f"{result} / {action}"
    )


students = [
    {"name": "민수", "score": 85, "attendance": 92},
    {"name": "지영", "score": 72, "attendance": 88},
    {"name": "현우", "score": 91, "attendance": 97},
    {"name": "서연", "score": 84, "attendance": 75}
]

for student in students:
    name = student["name"]
    score = student["score"]
    attendance = student["attendance"]

    result = get_result(score, attendance)
    action = get_action(result)
    summary = make_summary(
        name,
        score,
        attendance,
        result,
        action
    )

    print(summary)
```

이 코드에는 이번 범위의 핵심이 모두 들어 있습니다.

```text
List of Dictionaries
현재 항목
for 반복
복합 조건
and / or
조건 우선순위
책임 분리
함수 입력
return
반환값 저장
함수 결과를 다음 함수 입력으로 전달
최종 출력
```

# 24. 최종 체크리스트

## 자연어 요구사항 분석

- [ ] 긴 요구사항을 읽고 바로 코드를 작성하지 않는다.
- [ ] 요구사항에서 데이터 단서를 찾을 수 있다.
- [ ] `모든`, `각각`, `한 명씩` 같은 반복 단서를 찾을 수 있다.
- [ ] `이면`, `이상`, `그리고`, `또는`, `그 외` 같은 조건 단서를 찾을 수 있다.
- [ ] `판단`, `계산`, `저장`, `생성` 같은 처리 동사를 찾을 수 있다.
- [ ] 최종 출력 또는 저장 결과를 찾을 수 있다.
- [ ] 요구사항을 데이터 / 반복 / 조건 / 처리 / 결과로 정리할 수 있다.

## 조건과 반복

- [ ] AND와 OR를 자연어 요구사항에서 구분할 수 있다.
- [ ] 겹치는 조건의 우선순위를 결정할 수 있다.
- [ ] 경계값을 직접 골라 예상 결과를 작성할 수 있다.
- [ ] 반복 전 / 반복 중 / 반복 후를 구분할 수 있다.
- [ ] 결과를 출력할지 저장할지 구분할 수 있다.

## 함수와 데이터 흐름

- [ ] 긴 문제에서 서로 다른 책임을 찾을 수 있다.
- [ ] 함수가 필요한 역할과 필요하지 않은 역할을 판단할 수 있다.
- [ ] 역할을 먼저 정하고 함수 이름을 정할 수 있다.
- [ ] 함수의 입력 / 처리 / 결과를 설명할 수 있다.
- [ ] 함수가 너무 많은 책임을 가지는지 판단할 수 있다.
- [ ] return과 print의 차이를 요구사항 관점에서 설명할 수 있다.
- [ ] 반환값을 변수에 저장하는 이유를 설명할 수 있다.
- [ ] 한 함수의 결과를 다음 함수 입력으로 연결할 수 있다.
- [ ] 함수 사이에서 데이터가 끊기는 상황을 찾을 수 있다.
- [ ] 함수를 전체 프로그램과 분리해 테스트할 수 있다.

## 구현 전 사고

- [ ] 코드 전에 수도코드를 작성할 수 있다.
- [ ] 실행 전에 결과를 예상할 수 있다.
- [ ] 예상과 실제가 다르면 처음 달라진 단계를 찾을 수 있다.
- [ ] 자연어 → 구조 → 수도코드 → Python 코드 순서로 문제를 해결할 수 있다.

# 25. 이번 통합 실습의 최종 목표

이번 실습의 목표는 다음 코드를 외우는 것이 아닙니다.

```python
for ...
if ...
def ...
return ...
```

목표는 자연어 요구사항을 보았을 때 머릿속에서 다음 질문이 자동으로 떠오르는 것입니다.

```text
무슨 데이터가 필요한가?
무엇이 여러 개인가?
무엇을 하나씩 반복하는가?
언제 결과가 달라지는가?
무엇을 판단하거나 계산해야 하는가?
마지막에 무엇이 남아야 하는가?
서로 다른 역할은 무엇인가?
어떤 값이 다음 단계로 이동해야 하는가?
```

그리고 최종적으로 다음 흐름을 스스로 만들 수 있어야 합니다.

```text
자연어 요구사항
↓
데이터 / 반복 / 조건 / 처리 / 결과
↓
논리 블록
↓
책임 분리
↓
함수 입력 / 처리 / 결과
↓
데이터 흐름
↓
수도코드
↓
Python 코드
↓
예상과 실제 비교
```

> **문법을 아는 단계에서, 요구사항을 프로그램으로 설계할 수 있는 단계로 넘어가는 것이 이번 Chapter의 목표입니다.**
