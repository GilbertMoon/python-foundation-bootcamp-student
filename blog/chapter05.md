# Chapter 08·09·10 통합 실습 — 긴 요구사항을 작은 기능과 데이터 흐름으로 바꾸기

> **이번 실습의 목표는 Python 코드를 빨리 작성하는 것이 아닙니다.**  
> 실제 요구사항을 읽고 먼저 **데이터 / 반복 / 조건 / 처리 / 결과**를 찾아낸 뒤,  
> Chapter 08의 **복합 요구사항 분해**, Chapter 09의 **책임 분리와 함수 설계**, Chapter 10의 **함수 입력·출력과 연결**을 하나의 문제 해결 흐름으로 연결하여  
> **Python 코드를 작성하기 직전 단계인 수도코드와 함수 설계도까지 완성하는 것**이 목표입니다.

---

# 0. 이번 실습에서 가장 중요한 변화

앞에서는 문제를 보면 다음 구조를 먼저 찾았습니다.

```text
데이터
반복
조건
처리
결과
```

이번에는 요구사항이 더 길어집니다.

한 문장 안에 다음과 같은 내용이 함께 들어올 수 있습니다.

```text
여러 데이터를 반복해서 확인한다
여러 조건을 판단한다
조건에 따라 결과를 나눈다
계산 결과를 저장한다
여러 역할을 함수로 나눈다
함수의 결과를 다음 함수에 전달한다
최종 결과를 출력한다
```

이때 문제를 한 번에 코드로 바꾸려고 하면 쉽게 놓칩니다.

따라서 이번 실습에서는 반드시 다음 순서를 지킵니다.

```text
요구사항 읽기
↓
최종 결과 확인
↓
데이터 / 반복 / 조건 / 처리 / 결과 분리
↓
긴 요구사항을 작은 논리 블록으로 나누기
↓
조건의 관계와 우선순위 정하기
↓
서로 다른 역할 찾기
↓
함수 후보에 이름 붙이기
↓
각 함수의 입력 / 하는 일 / 결과 정리
↓
함수 사이에 어떤 값이 이동하는지 연결
↓
전체 프로그램 순서 작성
↓
예상 결과와 테스트값 작성
↓
수도코드 완성
↓
그 다음에 Python 코드 작성
```

> **이번 세 문제에서는 Python 정답 코드를 제공하지 않습니다.**  
> 학생이 직접 요구사항을 분석하고 **수도코드와 함수 설계도까지 완성하는 것**이 1차 목표입니다.

# 1. Chapter 08·09·10을 하나로 연결하면

세 Chapter의 핵심은 다음과 같습니다.

```text
Chapter 08
긴 요구사항을 작은 논리 블록으로 분해한다
→ 여러 조건 / 우선순위 / 반복 / 결과 저장

Chapter 09
큰 문제 안의 서로 다른 책임을 찾는다
→ 함수 후보 / 역할 이름 / 단일 책임

Chapter 10
작은 기능의 입력과 결과를 연결한다
→ parameter / return / 데이터 흐름 / 파이프라인
```

실제 프로그램에서는 이 세 가지가 따로 사용되지 않습니다.

예를 들어 다음 요구사항을 보겠습니다.

```text
학생 여러 명의 점수와 출석률을 확인한다.
점수가 90 이상이고 출석률이 80 이상이면 우수,
점수가 80 이상이고 출석률이 80 이상이면 수료,
그 외에는 보완 필요로 분류한다.
학생별 결과 문장을 만들고 마지막에 전체 평균 점수도 출력한다.
```

이 문제는 다음과 같이 나눌 수 있습니다.

```text
학생을 한 명씩 확인           → 반복
점수와 출석률 판단            → 복합 조건
우수 조건을 먼저 확인         → 조건 우선순위
학생 상태 결정                → 하나의 책임
결과 문장 만들기              → 또 다른 책임
전체 평균 계산                → 또 다른 책임
각 기능이 만든 값을 다음에 사용 → 함수 연결
```

문법보다 먼저 이 구조가 보여야 합니다.

# 3. Chapter 08 — 긴 요구사항을 분해할 때 보는 것

복합 요구사항에서는 다음 일곱 질문을 먼저 확인합니다.

```text
1. 데이터는 무엇인가?
2. 여러 개인 것은 무엇인가?
3. 무엇을 반복하는가?
4. 판단 기준은 몇 개인가?
5. 조건끼리 AND인가 OR인가?
6. 조건의 우선순위가 있는가?
7. 결과를 출력만 할 것인가, 저장할 것인가?
```

특히 조건이 겹치면 다음 질문이 중요합니다.

> **여러 조건을 동시에 만족하는 데이터가 있을 때 어떤 결과가 우선되는가?**

예를 들어:

```text
90 이상 → 우수
80 이상 → 수료
```

라면 `90 이상`은 `80 이상`에도 포함됩니다.

따라서 **더 특별한 조건과 더 일반적인 조건의 순서**를 먼저 결정해야 합니다.

# 4. Chapter 09 — 함수보다 먼저 책임을 찾습니다

함수는 `def` 문법부터 시작하지 않습니다.

먼저 긴 요구사항에서 **서로 다른 일**을 찾습니다.

예:

```text
상태 판단
등급 판단
평균 계산
메시지 생성
결과 출력
```

그다음 각 역할에 이름을 붙입니다.

함수 후보를 만들 때는 반드시 다음 책임 카드를 작성합니다.

```text
함수 이름:
입력:
하는 일:
결과:
```

예를 들어 어떤 함수가 점수 하나를 받아 상태를 결정한다면, 코드보다 먼저 다음이 설명되어야 합니다.

```text
입력
→ 점수

하는 일
→ 기준과 비교해서 상태 판단

결과
→ 판단 결과 문자열
```

중요한 원칙:

> **한 함수는 가능하면 한 가지 역할에 집중합니다.**

함수를 많이 만드는 것이 목표가 아니라, **문제의 서로 다른 책임이 더 잘 보이게 만드는 것**이 목표입니다.

---

# 5. Chapter 10 — 함수의 입출력과 연결을 먼저 그립니다

함수 여러 개를 나누었다고 프로그램이 끝난 것은 아닙니다.

이제 다음 질문에 답해야 합니다.

```text
이 함수는 무엇을 받는가?
이 함수가 만든 결과는 무엇인가?
그 결과를 누가 사용하는가?
다음 함수에는 어떤 값이 필요한가?
전체 호출 순서는 무엇인가?
```

함수를 작은 처리 기계라고 생각합니다.

```text
입력
↓
처리
↓
결과
```

그리고 여러 함수가 연결되면:

```text
원본 데이터
↓
기능 A
↓
A의 결과
↓
기능 B
↓
B의 결과
↓
기능 C
↓
최종 결과
```

이 흐름을 **데이터 흐름** 또는 **파이프라인**으로 생각하면 좋습니다.

# 6. `print`와 `return`을 설계 단계에서 구분합니다

이번 범위에서 반드시 구분해야 하는 내용입니다.

```text
print
→ 사람에게 화면으로 보여준다

return
→ 다음 코드가 사용할 값을 전달한다
```

함수의 결과를 다른 함수나 다음 처리에서 사용해야 한다면 단순히 화면에 보여주는 것만으로는 부족합니다.

따라서 함수 설계 카드에는 항상 다음 질문을 추가합니다.

```text
이 결과는 사람에게만 보여주면 되는가?
아니면 다음 처리에서 다시 사용해야 하는가?
```

다음 처리에서 필요하다면 **값이 함수 밖으로 전달되어야 한다는 점**을 수도코드에서 표현합니다.

## 9-1. 한 문장을 여러 논리 블록으로 나눕니다

먼저 코드를 생각하지 않고 다음처럼 역할을 나눕니다.

```text

B. 배송 여부 판단
C. 할인 대상 여부 판단
```

# 16. 다음 시간까지 직접 입력하고 암기할 코드

아래 코드는 **이번 세 실습의 정답 코드가 아닙니다.**

Chapter 11에서 오류를 찾고 디버깅하기 위한 **정상 동작 기준 코드**입니다.

복사해서 붙여 넣지 말고 직접 입력하세요.

```python
def get_result(score, attendance):
    if score >= 90 and attendance >= 80:
        return "우수"
    elif score >= 80 and attendance >= 80:
        return "수료"
    else:
        return "보완 필요"


def make_summary(name, score, attendance, result):
    return f"{name} / 점수 {score} / 출석 {attendance}% / {result}"


students = [
    {"name": "민수", "score": 85, "attendance": 92},
    {"name": "지영", "score": 72, "attendance": 88},
    {"name": "현우", "score": 91, "attendance": 97},
    {"name": "서연", "score": 84, "attendance": 75}
]

for student in students:
    name = student["name"]
    score = student["score"]
    attendance = student["attendance"]

    result = get_result(score, attendance)
    summary = make_summary(name, score, attendance, result)

    print(summary)
```

이 코드는 다음 내용을 모두 포함합니다.

```text
List of Dictionaries
반복
복합 조건
조건 우선순위
함수 분리
parameter
return
반환값 저장
함수 결과를 다음 함수에 전달
최종 출력
```

Chapter 11에서는 이 정상 코드의 일부를 일부러 잘못 바꾸었을 때 **어떤 단서로 원인을 찾을 수 있는지** 연습하게 됩니다.

# 21. 이번 실습의 한 문장

> **긴 요구사항을 작은 논리와 책임으로 나누고, 각 기능이 어떤 값을 받아 어떤 결과를 돌려주는지 연결하면 프로그램의 전체 흐름이 보이기 시작합니다.**

```text
요구사항
→ 구조 분해
→ 책임 분리
→ 함수 설계
→ 입력과 결과 정의
→ 함수 연결
→ 수도코드
→ Python 코드
```

이 순서를 스스로 만들 수 있으면 Chapter 08·09·10의 핵심을 하나의 문제 해결 과정으로 연결한 것입니다.
