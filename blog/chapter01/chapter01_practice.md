# Chapter 01 과제 실습 — 문제의 구조를 찾고 다른 문제로 옮겨 보기

> **이번 과제의 목표는 Python 코드를 많이 작성하는 것이 아닙니다.**  
> 문제를 보자마자 코드를 쓰는 습관을 줄이고, 먼저 **데이터 → 반복 → 조건 → 결과 → 코드**의 구조를 찾는 연습을 반복합니다.
>
> 이번 과제는 **하나의 Jupyter Notebook 파일(`.ipynb`)** 안에서 처음부터 끝까지 진행합니다.  
> 각 실습마다 **생각한 과정은 Markdown 셀**, 실제 실행 코드는 **Code 셀**에 기록합니다.

## 0. 과제를 시작하기 전에 꼭 읽어 주세요

이번 과제에서는 다음 순서를 계속 반복합니다.

```text
문제 읽기
   ↓
문제 구조 작성
   ↓
예상 결과 작성
   ↓
Python 코드 작성
   ↓
실행
   ↓
예상 결과와 비교
   ↓
필요하면 수정
```

가장 중요한 규칙은 하나입니다.

> **코드는 마지막에 작성합니다.**

문제를 읽자마자 `for`, `if`, `list`, `dict`부터 작성하지 않습니다.

먼저 다음 질문에 답합니다.

1. 어떤 데이터가 주어졌는가?
2. 여러 개인 것은 무엇인가?
3. 무엇을 하나씩 반복해야 하는가?
4. 무엇을 판단해야 하는가?
5. 계산하거나 바꿔야 하는 값이 있는가?
6. 최종적으로 무엇을 출력해야 하는가?

# 1. 이번 과제의 학습 목표

과제를 끝내면 다음을 할 수 있어야 합니다.

- 문제 문장에서 **데이터 / 반복 / 조건 / 결과**를 구분할 수 있다.
- 여러 데이터를 `List`와 `Dictionary` 형태로 표현할 수 있다.
- 여러 데이터를 `for`로 하나씩 확인할 수 있다.
- Dictionary에서 필요한 값을 꺼낼 수 있다.
- `if / else`를 이용해 기준에 따라 결과를 만들 수 있다.
- `print()`로 필요한 결과를 출력할 수 있다.
- 소재가 달라져도 같은 문제 해결 구조를 찾을 수 있다.
- 코드를 작성하기 전에 전체 구조를 먼저 설명할 수 있다.
- AI를 정답 생성 도구가 아니라 **학습 보조 도구**로 제한해서 사용할 수 있다.
- 모든 실습 과정을 하나의 Notebook으로 정리하고 GitHub URL로 제출할 수 있다.

# 2. 제출 방식

# 4. AI 사용 규칙

이번 과제에서는 AI 사용을 허용합니다.

하지만 **정답이나 코드를 얻기 위한 질문은 절대 금지**입니다.

AI는 문제를 대신 풀어 주는 도구가 아니라, 내가 공부하는 과정에서 아주 제한적으로 사용하는 보조 도구입니다.

---

## AI에게 질문해도 되는 것

다음과 같은 질문은 가능합니다.

```text
"Python에서 Dictionary라는 용어가 무엇을 의미하는지 설명해 줘."
"for 반복문의 일반적인 역할을 코드 없이 설명해 줘."
"이 오류 메시지가 일반적으로 어떤 의미인지 설명해 줘. 해결 코드는 말하지 마."
"GitHub에 ipynb 파일을 올리는 방법을 알려 줘."
"Markdown 셀과 Code 셀의 차이를 설명해 줘."
```

---

## AI에게 질문하면 안 되는 것

다음 질문은 금지합니다.

```text
"이 문제 풀어 줘."
"정답 코드 작성해 줘."
"for문으로 코드를 만들어 줘."
"내 코드 완성해 줘."
"내 코드 어디가 틀렸는지 고쳐 줘."
"이 조건을 if문으로 만들어 줘."
"학생 점수 문제의 구조를 대신 정리해 줘."
"정답과 내 코드를 비교해 줘."
"더 좋은 코드로 바꿔 줘."
```

문제 자체를 AI에게 붙여 넣고 해결 순서나 정답 구조를 요구하는 것도 금지입니다.

> **AI가 내 대신 문제를 분해하거나 코드를 작성하면 이번 과제의 학습 목표가 사라집니다.**

---

## AI 질문 횟수

가능하면 **AI 질문 0회**를 목표로 합니다.

정말 필요한 경우에도 전체 과제를 수행하면서 **3회 이내 사용을 권장**합니다.

질문하기 전에 반드시 다음을 먼저 적습니다.

```markdown
### AI 질문 전 기록

- 내가 먼저 생각한 내용:
- 공식 문서에서 찾아본 내용:
- 그래도 해결되지 않은 이유:
```

# 5. 코드 참고 규칙 — Python 공식 튜토리얼만 사용

코드 문법이 기억나지 않는 경우 인터넷 검색으로 정답 코드를 찾지 않습니다.

이번 과제에서 코드 참고는 **Python 공식 튜토리얼**만 사용합니다.

- Python 공식 튜토리얼  
  https://docs.python.org/ko/3/tutorial/

- 제어 흐름 도구 (`if`, `for` 등)  
  https://docs.python.org/ko/3/tutorial/controlflow.html

- 자료구조 (`list`, `dict` 등)  
  https://docs.python.org/ko/3/tutorial/datastructures.html

- 입력과 출력  
  https://docs.python.org/ko/3/tutorial/inputoutput.html

문법이 기억나지 않을 때는 다음 순서로 진행합니다.

```text
1. 먼저 기억나는 대로 작성
2. 실행
3. 무엇이 기억나지 않는지 정확히 적기
4. Python 공식 튜토리얼 확인
5. 문서를 닫기
6. 다시 직접 작성
```

블로그, Stack Overflow, 다른 사람 GitHub 코드, AI가 생성한 코드 등을 복사하지 않습니다.

# 20. Chapter 02 준비 코드 — 반드시 직접 입력

```python
students = [
    {"name": "민수", "score": 95, "attendance": 90},
    {"name": "지영", "score": 85, "attendance": 95},
    {"name": "현우", "score": 72, "attendance": 65},
    {"name": "수진", "score": 78, "attendance": 88}
]

for student in students:
    name = student["name"]
    score = student["score"]
    attendance = student["attendance"]

    if score < 60 or attendance < 70:
        grade = "F"
    elif score >= 90 and attendance >= 80:
        grade = "A"
    elif score >= 80 and attendance >= 80:
        grade = "B"
    elif score >= 70:
        grade = "C"
    else:
        grade = "D"

    print(
        f"{name}: 점수 {score}점, "
        f"출석률 {attendance}%, 등급 {grade}"
    )
```

# 32. 이번 과제에서 가장 중요한 것

이번 과제의 점수보다 더 중요한 것은 다음 습관을 만드는 것입니다.

```text
문제를 읽는다
↓
구조를 찾는다
↓
순서를 생각한다
↓
예상한다
↓
코드를 작성한다
↓
실행한다
↓
비교한다
```

문제가 달라질 때마다 새로운 정답 코드를 외우는 것이 목표가 아닙니다.

학생 성적, 쇼핑몰 주문, 상품 재고, 출석률, 기온, 회원 구매액은 서로 다른 문제처럼 보이지만 다음 구조를 공유할 수 있습니다.

```text
여러 데이터
↓
하나씩 확인
↓
필요한 값 확인
↓
기준과 비교
↓
결과 생성
↓
출력
```

이 구조가 눈에 보이기 시작하면 Python 문제를 만났을 때

> **“어떤 문법을 써야 하지?”**

보다 먼저

> **“이 문제의 데이터, 반복, 조건, 결과는 무엇이지?”**

라고 생각할 수 있게 됩니다.

그것이 Chapter 01의 목표입니다.

다음 Chapter에서는 이 구조를 다시

> **컴퓨터가 실제로 실행할 수 있는 작은 단계와 올바른 순서**

로 나누는 연습을 진행합니다.
