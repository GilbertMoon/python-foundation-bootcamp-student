# Chapter 01. 문제를 보면 코드부터 쓰지 않는다

> **이번 Chapter의 핵심은 Python 문법이 아닙니다.**  
> 문제를 읽자마자 코드를 쓰는 습관을 멈추고, 먼저 **문제의 구조를 찾는 습관**을 만드는 것이 목표입니다.

---

## 1강에서 가장 먼저 바꿀 습관

Python을 처음 배우고 나면 문제를 보자마자 이런 생각을 하기 쉽습니다.

- `if`를 써야 하나?
- `for`문을 써야 하나?
- List를 만들어야 하나?
- Dictionary를 써야 하나?
- 함수부터 만들어야 하나?

그런데 이런 질문부터 시작하면 조금만 문제가 달라져도 막히기 쉽습니다.

왜냐하면 **문법부터 찾고 있기 때문**입니다.

이번 Bootcamp에서는 순서를 바꿉니다.

> **코드는 마지막에 작성합니다.**

먼저 문제를 읽고 다음 다섯 가지를 찾습니다.

1. 어떤 데이터가 주어졌는가?
2. 무엇을 반복해야 하는가?
3. 무엇을 판단해야 하는가?
4. 무엇을 계산하거나 바꿔야 하는가?
5. 최종 결과는 무엇인가?

![문제에서 구조를 찾는 두 가지 접근](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter01/problem-to-structure.jpg)

왼쪽처럼 `문제 → 바로 코드`로 가면 중간에 막혔을 때 어디가 잘못되었는지 찾기 어렵습니다.

반대로 오른쪽처럼 먼저 구조를 찾으면 코드가 아직 없어도 문제를 설명할 수 있습니다.

```text
문제
 ↓
데이터
 ↓
반복
 ↓
조건
 ↓
결과
 ↓
코드
```

이 순서를 앞으로 계속 사용합니다.

## 1. 수업 시작 — 0강 코드를 5분 안에 작성해 봅니다

먼저 아무 자료도 보지 않고 0강의 기본 코드를 작성합니다.

```python
students = [
    {"name": "민수", "score": 85},
    {"name": "지영", "score": 72},
    {"name": "현우", "score": 91}
]

for student in students:
    name = student["name"]
    score = student["score"]

    if score >= 80:
        result = "합격"
    else:
        result = "불합격"

    print(name, score, result)
```

중요한 점은 단순히 외워서 적는 것만이 아닙니다.

작성한 뒤 다음 질문에 답할 수 있어야 합니다.

- 왜 `students`는 List인가요?
- 왜 학생 한 명은 Dictionary인가요?
- 왜 `for`가 필요한가요?
- `if`는 무엇을 판단하나요?
- `80`은 어떤 의미인가요?
- 최종 결과는 무엇인가요?

이 질문에 답할 수 있다면 코드를 단순히 글자로 외운 것이 아니라 **구조까지 이해하고 있는 것**입니다.

## 2. 이제 코드를 잠시 잊어봅시다

다음 문제를 읽어 보세요.

> 여러 학생의 이름과 점수가 주어져 있습니다.  
> 학생을 한 명씩 확인해서 점수가 80점 이상이면 `합격`, 그렇지 않으면 `불합격`이라고 출력하세요.

코드를 작성하지 마세요.

먼저 문제를 사람의 말로 나눠 봅니다.

### 데이터는 무엇인가요?

학생의 이름과 점수입니다.

```text
민수 / 85
지영 / 72
현우 / 91
```

### 여러 개인 것은 무엇인가요?

학생이 여러 명입니다.

따라서 학생들을 **하나씩 확인해야 합니다.**

### 판단해야 하는 것은 무엇인가요?

점수가 80점 이상인지 판단해야 합니다.

### 결과는 무엇인가요?

학생별로 `합격` 또는 `불합격`을 출력해야 합니다.

즉 코드를 전혀 쓰지 않아도 문제 구조를 이렇게 표현할 수 있습니다.

```text
학생 여러 명
   ↓
한 명씩 확인
   ↓
점수 확인
   ↓
80점 이상인가?
   ↓
합격 / 불합격
```

이것이 먼저입니다.

Python 코드는 이 구조를 **컴퓨터가 실행할 수 있는 형태로 번역한 것**입니다.

## 3. 문제 문장에서 중요한 단어를 찾아봅시다

프로그래밍 문제를 읽을 때 모든 문장을 똑같이 볼 필요는 없습니다.

문장 안에는 역할이 다른 단어가 섞여 있습니다.

예를 들어 다음 문제를 다시 봅니다.

> 여러 학생의 이름과 점수가 주어져 있습니다. 학생을 한 명씩 확인해서 점수가 80점 이상이면 합격, 그렇지 않으면 불합격이라고 출력하세요.

이 문장을 다음처럼 나눌 수 있습니다.

- **데이터**: 학생, 이름, 점수
- **반복**: 학생을 한 명씩 확인
- **조건**: 점수 80점 이상
- **결과**: 합격 또는 불합격 출력

![문제 문장을 데이터·반복·조건·결과로 나누기](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter01/problem-sentence-breakdown.jpg)

앞으로 문제를 읽을 때는 형광펜으로 표시하듯 머릿속에서 구분해 보세요.

> **명사만 보는 것이 아니라, 데이터와 행동과 판단을 구분합니다.**

## 4. 새로운 문제를 하나 보겠습니다

이번에는 학생 문제가 아닙니다.

다음은 쇼핑몰 주문 문제입니다.

> 여러 고객의 이름과 주문 금액이 주어져 있습니다.  
> 고객을 한 명씩 확인해서 주문 금액이 50,000원 이상이면 `무료배송`, 그렇지 않으면 `배송비 있음`이라고 출력하세요.

학생 성적 문제와 완전히 다른 문제처럼 보이나요?

먼저 코드는 쓰지 않고 구조만 찾아봅니다.

### 데이터

고객 이름과 주문 금액입니다.

예를 들어:

```text
민수 / 45000
지영 / 72000
현우 / 53000
```

### 반복

고객이 여러 명이므로 한 명씩 확인합니다.

### 조건

주문 금액이 50,000원 이상인지 판단합니다.

### 결과

- 50,000원 이상 → 무료배송
- 그 외 → 배송비 있음

정리하면:

```text
고객 여러 명
   ↓
한 명씩 확인
   ↓
주문 금액 확인
   ↓
50,000원 이상인가?
   ↓
무료배송 / 배송비 있음
```

어디서 많이 본 구조 아닌가요?

## 6. 문제의 단어를 Python의 역할로 연결해 봅시다

쇼핑몰 문제를 다시 보겠습니다.

> 여러 고객의 이름과 주문 금액이 주어져 있습니다. 고객을 한 명씩 확인해서 주문 금액이 50,000원 이상이면 무료배송, 그렇지 않으면 배송비 있음이라고 출력하세요.

이제 문제의 구조와 Python 도구를 연결합니다.

| 문제에서 발견한 것 | Python에서 사용할 도구 |
|---|---|
| 고객이 여러 명이다 | List |
| 고객 한 명에게 이름과 주문 금액이 있다 | Dictionary |
| 고객을 한 명씩 확인한다 | for |
| 주문 금액을 확인한다 | 변수 / Dictionary 조회 |
| 50,000원 이상인지 판단한다 | if / else |
| 배송 결과를 보여준다 | print |

여기서 중요한 순서를 다시 확인합니다.

```text
문제를 읽는다
   ↓
구조를 찾는다
   ↓
필요한 Python 도구를 고른다
   ↓
코드를 작성한다
```

반대가 아닙니다.

```text
문제
 ↓
무조건 for부터 작성
 ↓
무조건 if 작성
 ↓
중간에 막힘
```

이 습관을 바꾸는 것이 이번 수업의 핵심입니다.

## 10. 전체 코드를 확인해 봅시다

```python
orders = [
    {"customer": "민수", "amount": 45000},
    {"customer": "지영", "amount": 72000},
    {"customer": "현우", "amount": 53000}
]

for order in orders:
    customer = order["customer"]
    amount = order["amount"]

    if amount >= 50000:
        result = "무료배송"
    else:
        result = "배송비 있음"

    print(customer, amount, result)
```

실행하기 전에 결과를 예상해 봅니다.

```text
민수 45000 배송비 있음
지영 72000 무료배송
현우 53000 무료배송
```

그 다음에 실행합니다.

> **예상 → 실행 → 비교**

이 순서도 앞으로 계속 반복합니다.

코드는 달라져도 구조를 찾을 수 있다면 처음 보는 문제도 훨씬 덜 어렵습니다.

## 12. 문제를 읽으면 먼저 이 다섯 칸을 채워 보세요

앞으로 실습할 때 코드 편집기를 바로 열지 않습니다.

먼저 아래 내용을 작성합니다.

### ① 데이터

무엇이 주어졌나요?

```text

```

### ② 반복

여러 개인 것은 무엇이고, 무엇을 하나씩 확인해야 하나요?

```text
예: 여러 주문을 하나씩 확인
```

### ③ 조건

어떤 기준으로 판단해야 하나요?

```text

```

### ④ 처리

조건에 따라 무엇을 바꾸거나 계산해야 하나요?

```text
예: 무료배송 여부 결정
```

### ⑤ 결과

최종적으로 무엇을 보여줘야 하나요?

```text
예: 고객 이름, 주문 금액, 배송 결과
```

이 다섯 칸을 채우지 못한다면 아직 코드를 작성할 때가 아닙니다.

## 15. 직접 해보기 ③ — 기준값을 바꾸면 무엇이 달라질까요?

주문 문제에서 무료배송 기준이 50,000원이 아니라 30,000원으로 바뀌었습니다.

질문에 먼저 답해 보세요.

1. 데이터 구조가 바뀌나요?
2. 반복 구조가 바뀌나요?
3. 조건에서 무엇이 바뀌나요?
4. 출력 구조가 바뀌나요?

정답은 코드를 작성하기 전에 말할 수 있어야 합니다.

이런 식으로 **무엇이 바뀌고 무엇이 그대로인지 구분하는 것**도 중요한 프로그래밍 사고입니다.

---

## 16. 직접 해보기 ④ — 결과 문구만 바꾸기

다음과 같이 요구사항이 바뀌었습니다.

- 50,000원 이상 → `FREE`
- 그 외 → `PAID`

이 경우 프로그램 전체 구조를 새로 만들어야 할까요?

아닙니다.

바뀌는 부분은 결과 문구입니다.

```python
if amount >= 50000:
    result = "FREE"
else:
    result = "PAID"
```

문제가 조금 바뀌었다고 모든 코드를 다시 생각할 필요는 없습니다.

---

## 17. 초보자가 자주 하는 실수 ① — 문제를 읽자마자 코딩하기

문제를 읽자마자 다음처럼 시작합니다.

```python
for ...
```

그런데 무엇을 반복하는지 아직 정하지 않았습니다.

그러면 금방 손이 멈춥니다.

먼저 물어야 합니다.

> **여러 개인 것은 무엇이지?**

그 답을 찾은 뒤 반복을 생각합니다.

---

## 18. 초보자가 자주 하는 실수 ② — 예제의 단어를 그대로 외우기

학생 문제를 외운 뒤 주문 문제에서도 `students`, `score` 같은 이름을 그대로 사용하려는 경우가 있습니다.

하지만 중요한 것은 변수 이름이 아닙니다.

중요한 것은 역할입니다.

```text
students  → 여러 대상
student   → 현재 대상 하나
score     → 판단할 값
80        → 판단 기준
result    → 판단 결과
```

주문 문제에서는 같은 역할이 이렇게 바뀝니다.

```text
orders    → 여러 대상
order     → 현재 대상 하나
amount    → 판단할 값
50000     → 판단 기준
result    → 판단 결과
```

> **이름을 외우지 말고 역할을 이해하세요.**

---

## 19. 초보자가 자주 하는 실수 ③ — 실행부터 하고 생각하기

코드를 작성하고 바로 실행하면 결과가 나오기는 합니다.

하지만 실력이 빨리 늘려면 실행 전에 먼저 예상해야 합니다.

예를 들어:

```python
amount = 45000
```

이라면 실행 전에 말해 봅니다.

```text
45000 >= 50000 → False
따라서 배송비 있음
```

예상과 실제 결과가 다르면 그 차이가 중요한 학습 자료가 됩니다.

---

## 20. 이번 Bootcamp에서 AI와 검색을 사용하는 규칙

핵심 문제 해결 시간에는 **AI에게 정답 코드를 먼저 묻지 않습니다.**

일반 검색으로 정답 예제를 찾는 것도 하지 않습니다.

문제가 막히면 다음 순서를 지킵니다.

```text
1. 문제를 다시 읽는다
2. 데이터 / 반복 / 조건 / 결과를 다시 적는다
3. 내가 알고 있는 Python 문법으로 시도한다
4. 필요한 경우 Python 공식 문서를 확인한다
5. 직접 실행하고 오류를 확인한다
6. 수정한다
7. 마지막에 AI로 설명·검증한다
```

AI를 사용하지 않는 것이 목표가 아닙니다.

> **AI에게 생각을 맡기기 전에 내가 먼저 생각하는 습관을 만드는 것**이 목표입니다.

## 21. Python 공식 문서는 어떻게 사용할까요?

이번 과정에서는 필요한 경우 Python 공식 문서를 참고할 수 있습니다.

예를 들어 기억이 나지 않는 문법이 있다면 정답 코드를 검색하기보다 공식 문서에서 해당 기능의 사용법을 확인합니다.

하지만 공식 문서도 문제의 답을 대신 만들어 주지는 않습니다.

문서에서 확인해야 하는 것은:

- `for`의 사용 방법
- List의 기본 사용법
- Dictionary에서 값 조회 방법
- 비교 연산자의 의미
- `if / else`의 문법

등입니다.

**어떤 문법이 필요한지를 판단하는 것은 여러분의 몫입니다.**

## 22. 오늘의 핵심 사고를 한 문장으로 정리하면

문제가 나오면 이렇게 생각합니다.

```text

```

가 아니라:

```text

```

입니다.

그리고 다음 순서를 사용합니다.

```text
데이터
 ↓
반복
 ↓
조건
 ↓
처리
 ↓
결과
 ↓
Python 코드
```

이 순서가 익숙해지는 것이 1강의 목표입니다.

# Chapter 01 핵심 정리

오늘 반드시 기억해야 할 것은 Python 문법 하나가 아닙니다.

> **문제를 보면 코드부터 쓰지 않는다.**

먼저 다음 다섯 가지를 찾습니다.

```text
1. 데이터는 무엇인가?
2. 무엇을 반복하는가?
3. 무엇을 판단하는가?
4. 무엇을 처리하거나 바꾸는가?
5. 최종 결과는 무엇인가?
```

학생 성적 문제와 쇼핑몰 주문 문제는 겉모습은 달랐지만 내부 구조는 같았습니다.

```text
여러 대상
 ↓
하나씩 확인
 ↓
필요한 값 확인
 ↓
기준과 비교
 ↓
결과 생성
```

앞으로 처음 보는 문제를 만났을 때도 이 구조부터 찾아보세요.

> **문법을 외우는 사람에서, 문제의 구조를 찾는 사람으로.**
