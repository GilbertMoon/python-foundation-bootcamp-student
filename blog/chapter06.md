# 3. 요구사항 문장에 직접 표시하는 방법

예를 들어 다음 요구사항이 있습니다.

> **결제가 완료된 주문만 처리합니다. 결제 완료 주문의 개수를 세고 총 금액을 계산합니다. 주문 금액이 50,000원 이상이면 무료배송으로 표시합니다. 마지막에 주문 수와 총 금액을 출력합니다.**

코드를 보기 전에 다음처럼 표시합니다.

```text
[조건/필터] 결제가 완료된 주문만 처리

[처리/집계] 결제 완료 주문의 개수를 센다
[처리/집계] 결제 완료 주문의 총 금액을 계산한다

[조건] 주문 금액 >= 50,000
[결과] 무료배송

[결과] 반복이 끝난 뒤 주문 수와 총 금액 출력
```

그리고 문장에 직접 적혀 있지 않은 데이터와 반복을 보완합니다.

```text
[데이터]
- 주문 목록
- 현재 주문
- 고객명
- 주문 금액
- 결제 여부

[반복]
- 주문을 한 건씩 확인
```

이제 코드가 요구사항과 맞는지 비교할 기준이 생겼습니다.

# 4. 디버깅의 핵심 — 요구사항, 코드, 실제 결과를 삼각형으로 비교합니다

디버깅할 때 코드만 보지 않습니다.

```text
          요구사항
          /      \
         /        \
      코드 ------ 실제 결과
```

세 방향을 모두 확인합니다.

### 요구사항 ↔ 코드

```text
이상이라고 했는데 >를 썼는가?
모든 항목을 처리해야 하는데 반복문이 빠졌는가?
누적해야 하는데 매번 값을 덮어쓰는가?
반복마다 출력해야 하는데 print가 반복 밖에 있는가?
```

### 코드 ↔ 실제 결과

```text
이 줄 이후 변수 값은 무엇인가?
현재 반복에서 count가 몇인가?
함수 호출 결과는 무엇인가?
실제 자료형은 무엇인가?
```

### 요구사항 ↔ 실제 결과

```text
50,000원이 무료배송으로 나오는가?
결제되지 않은 주문이 합계에 포함되지 않는가?
세 명을 출력해야 하는데 한 명만 출력되지는 않는가?
평균의 분모가 처리 대상 수와 일치하는가?
```

> **좋은 디버깅은 코드를 오래 바라보는 것이 아니라, 세 가지 사이의 불일치를 좁혀 가는 과정입니다.**

# 5. 오류를 만나면 먼저 세 종류를 구분합니다

## ① 문법 오류

Python 문법 자체가 맞지 않아 정상적으로 실행되지 않습니다.

확인할 것:

```text
콜론(:)이 빠졌는가?
괄호가 맞는가?
들여쓰기가 문법적으로 가능한가?
문자열 따옴표가 닫혔는가?
```

예:

```python
if score >= 80
    print("합격")
```

---

## ② 실행 오류

문법은 맞지만 실행 도중 문제가 발생합니다.

예:

```text
KeyError
TypeError
NameError
```

확인할 것:

```text
Dictionary key가 실제로 존재하는가?
내가 예상한 자료형과 실제 자료형이 같은가?
변수 이름이 맞는가?
함수에 필요한 인수를 전달했는가?
```

---

## ③ 논리 오류

코드는 끝까지 실행되지만 결과가 요구사항과 다릅니다.

예:

```text
80점 이상이어야 하는데 80점이 탈락한다.
결제 완료 주문 수가 3이어야 하는데 1이 나온다.
학생 세 명을 출력해야 하는데 마지막 학생만 출력된다.
총액이 누적되어야 하는데 마지막 금액만 남는다.
함수에서 값은 계산했지만 호출 결과는 None이다.
```

논리 오류에는 오류 메시지가 없을 수 있습니다.

그래서 다음이 반드시 필요합니다.

> **실행 전에 예상 결과를 만들어 둔다.**

# 6. 이번 실습에서 사용할 디버깅 9단계

오류가 발생하면 아래 순서를 사용합니다.

```text
1. 요구사항 기준 예상 결과를 적는다.
2. 실제 결과를 확인한다.
3. 둘이 처음 달라지는 위치를 찾는다.
4. 그 위치와 관련된 변수 값을 확인한다.
5. 예상한 자료형과 실제 자료형을 확인한다.
6. 원인 가설을 한 문장으로 적는다.
7. 가설과 관련된 한 부분만 수정한다.
8. 다시 실행한다.
9. 예상 결과와 다시 비교한다.
```

가장 중요한 규칙:

```text
가설 하나
↓
수정 하나
↓
재실행
↓
검증
```

한 번에 여러 곳을 고치면 결과가 맞아져도 **무엇이 원인이었는지 배울 수 없습니다.**


질문:


# 8. 반복 문제는 반드시 반복 전 / 반복 중 / 반복 후로 나눕니다

많은 논리 오류는 코드 문법보다 **실행 위치**에서 발생합니다.

다음처럼 나눠 봅니다.

```text
반복 전
→ 한 번만 준비할 값

반복 중
→ 현재 항목마다 실행할 일

반복 후
→ 모든 항목 처리가 끝난 뒤 한 번 실행할 일
```

예: 결제 주문 처리

```text
반복 전
- paid_count = 0
- total_amount = 0

반복 중
- 현재 주문 확인
- 결제 여부 판단
- count 누적
- amount 누적
- 배송 상태 판단
- 현재 주문 결과 출력

반복 후
- 총 주문 수 출력
- 총 금액 출력
- 평균 계산 및 출력
```

이 구분을 먼저 하면 들여쓰기 오류를 훨씬 쉽게 찾을 수 있습니다.

# 11. 문제 2 — 여러 주문 처리 프로그램 디버깅

주문 한 건은 다음 정보를 가집니다.

```text
고객명
주문 금액
결제 여부
```

주문은 여러 건입니다.

요구사항:

```text
1. 결제가 완료된 주문만 처리한다.
2. 결제 완료 주문의 개수를 센다.
3. 결제 완료 주문의 총 금액을 계산한다.
4. 50,000원 이상이면 무료배송으로 표시한다.
5. 50,000원 미만이면 배송비 발생으로 표시한다.
6. 각 결제 완료 주문의 고객명과 배송 결과를 출력한다.
7. 반복이 끝난 뒤 결제 완료 주문 수와 총 금액을 출력한다.
```

아래 프로그램은 일부 요구사항을 정확히 만족하지 않을 수 있습니다.

```python
orders = [
    {"customer": "민수", "amount": 48000, "paid": True},
    {"customer": "지영", "amount": 72000, "paid": True},
    {"customer": "현우", "amount": 35000, "paid": False},
    {"customer": "서연", "amount": 50000, "paid": True}
]

paid_count = 0
total_amount = 0

for order in orders:
    if order["paid"]:
        paid_count = 1
        total_amount = order["amount"]

        if order["amount"] > 50000:
            delivery = "무료배송"
        else:
            delivery = "배송비 발생"

print(order["customer"], delivery)
print("결제 완료 주문 수:", paid_count)
print("총 주문 금액:", total_amount)
```

# 14. 자주 하는 잘못된 접근과 교정 방법

## 잘못된 접근 1 — 오류가 보이면 코드를 즉시 수정한다

교정:

```text

→ 차이
→ 가설
→ 수정
```

## 잘못된 접근 2 — 오류 메시지가 없으면 맞다고 생각한다

문제:

```text
논리 오류는 오류 메시지가 없을 수 있다.
```

교정:

```text
요구사항 기준 예상 결과와 비교한다.
```

---

## 잘못된 접근 3 — 여러 곳을 한 번에 수정한다

문제:

```text
무엇이 원인이었는지 알 수 없다.
새로운 오류를 동시에 만들 수 있다.
```

교정:

```text
가설 하나
→ 수정 하나
→ 재실행
```

---

## 잘못된 접근 4 — 반복문에서 현재 값만 본다

문제:

```text

```

교정:

```text
처리 전 값
→ 현재 데이터
→ 처리 후 값
```

을 함께 추적합니다.

---

## 잘못된 접근 5 — print 위치를 단순한 들여쓰기 문제로 본다

교정:

```text
이 출력은 항목마다 필요한가?
아니면 전체 처리 후 한 번 필요한가?
```

를 먼저 묻습니다.

이번 실습에서도 AI는 **정답 생성기**가 아니라 마지막 검토자입니다.

## 1단계 — AI 없이 먼저 작성

```text
문제 재설명

직접 실행
원인 가설
```

---

## 2단계 — 필요한 경우 공식 문서 확인

정확한 문법이나 표준 동작이 기억나지 않을 때 확인합니다.

예:

```text
Dictionary key 접근

continue 동작
type() 사용법
```

---

## 3단계 — AI에게 가설을 검토받습니다

좋은 질문 예:

```text
"요구사항은 50,000원 이상 무료배송입니다.
제가 50,000에서 배송비 발생이 나오는 것을 확인했고,
코드의 > 연산자가 원인이라고 가설을 세웠습니다.
정답 코드는 작성하지 말고 이 원인 분석이 타당한지만 검토해 주세요."
```

```text
"예상 주문 수는 3인데 실제로 1이 나왔습니다.
반복할 때 count를 누적하지 않고 1로 다시 대입한 것이 원인이라고 생각합니다.
전체 코드를 고치지 말고 제 가설만 검토해 주세요."
```

```text
"제가 재고 관리 요구사항을 데이터 / 반복 / 조건 / 처리 / 결과로 나눴습니다.
정답 코드 없이 빠진 요구사항만 확인해 주세요."
```

피해야 하는 질문:

```text
"이 문제 풀어 주세요."
"정답 코드 작성해 주세요."
"오류 전부 고쳐 주세요."
"수도코드 대신 작성해 주세요."
"어디가 틀렸는지 바로 알려 주세요."
```

> **AI 없이 개발하는 것이 목표가 아니라, AI에게 생각의 첫 단계를 맡기지 않는 것이 목표입니다.**

```python
def get_delivery_result(amount):
    if amount >= 50000:
        return "무료배송"
    return "배송비 발생"


orders = [
    {"customer": "민수", "amount": 48000, "paid": True},
    {"customer": "지영", "amount": 72000, "paid": True},
    {"customer": "현우", "amount": 35000, "paid": False},
    {"customer": "서연", "amount": 91000, "paid": True}
]

paid_count = 0
total_amount = 0
highest_amount = None

for order in orders:
    if not order["paid"]:
        continue

    customer = order["customer"]
    amount = order["amount"]

    paid_count = paid_count + 1
    total_amount = total_amount + amount

    if highest_amount is None or amount > highest_amount:
        highest_amount = amount

    delivery = get_delivery_result(amount)
    print(customer, amount, delivery)

if paid_count > 0:
    average_amount = total_amount / paid_count
else:
    average_amount = 0

print("결제 완료 주문 수:", paid_count)
print("총 주문 금액:", total_amount)
print("평균 주문 금액:", average_amount)
print("최고 주문 금액:", highest_amount)
```
