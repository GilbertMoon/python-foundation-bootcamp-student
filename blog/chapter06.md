# 1. 이번에도 자연어 요구사항에서 다섯 가지부터 찾습니다

디버깅 문제라고 해서 바로 코드를 보지 않습니다.

먼저 요구사항에서 다음 다섯 가지를 찾습니다.

```text
데이터
반복
조건
처리
결과
```

올바른 요구사항 기준이 있어야 코드가 틀렸는지 판단할 수 있기 때문입니다.

---

## 1-1. 데이터 — 무엇을 가지고 일하는가?

자연어에서 주로 **명사**를 찾습니다.

예:

```text
학생
점수
주문
주문 금액
결제 여부
상품
가격
재고
판매중 여부
```

질문:

```text
무엇을 입력으로 가지고 있는가?
현재 처리 중인 한 개는 무엇인가?
한 개의 대상은 어떤 속성을 가지는가?
여러 개의 대상은 어떤 구조로 묶을 수 있는가?
```

---

## 1-2. 반복 — 무엇이 여러 개이고 무엇을 하나씩 처리하는가?

다음 표현을 찾습니다.

```text
모든
각각
하나씩
한 명씩
여러 주문
여러 상품
전체
```

예:

> 모든 주문을 한 건씩 확인하세요.

코드보다 먼저 다음 구조를 떠올립니다.

```text
여러 주문
↓
현재 주문 한 건
↓
필요한 처리
↓
다음 주문
```

---

## 1-3. 조건 — 언제 결과가 달라지는가?

다음 표현을 찾습니다.

```text
이면
이상이면
초과하면
이하면
미만이면
같으면
그리고
면서
또는
거나
그 외
그렇지 않으면
```

디버깅에서는 자연어와 비교 연산자를 정확히 대응시켜야 합니다.

```text
이상 → >=
초과 → >
이하 → <=
미만 → <
```

예:

> 주문 금액이 50,000원 이상이면 무료배송입니다.

```text
판단 대상: 주문 금액
기준값: 50,000
경계 포함 여부: 포함
조건: amount >= 50000
결과: 무료배송
```


처리 동사는 코드의 역할을 찾는 단서입니다.


질문:

```text

화면에 보여주면 끝나는가?
다음 처리에서 다시 사용하는가?
```

# 3. 요구사항 문장에 직접 표시하는 방법

예를 들어 다음 요구사항이 있습니다.

> **결제가 완료된 주문만 처리합니다. 결제 완료 주문의 개수를 세고 총 금액을 계산합니다. 주문 금액이 50,000원 이상이면 무료배송으로 표시합니다. 각 결제 완료 주문의 고객명과 배송 결과를 출력하고, 마지막에는 주문 수와 총 금액을 출력합니다.**

다음처럼 표시합니다.

```text
[조건/필터] 결제가 완료된 주문만 처리

[처리/집계] 결제 완료 주문의 개수를 센다
[처리/집계] 결제 완료 주문의 총 금액을 계산한다

[조건] 주문 금액 >= 50,000
[결과] 무료배송

[반복 중 결과] 각 결제 완료 주문의 고객명과 배송 결과 출력

[반복 후 결과] 주문 수와 총 금액 출력
```

문장에 직접 쓰이지 않은 데이터와 반복도 보완합니다.

```text
[데이터]
- 주문 목록
- 현재 주문
- 고객명
- 주문 금액
- 결제 여부

[반복]
- 주문을 한 건씩 확인
```

이제 코드를 비교할 기준이 생겼습니다.

# 4. 디버깅의 핵심 — 요구사항, 코드, 실제 결과를 삼각형으로 비교합니다

```text
          요구사항
          /      \
         /        \
      코드 ------ 실제 결과
```

## 요구사항 ↔ 코드

```text
'이상'인데 >를 사용하지 않았는가?
'모든 항목'인데 반복이 빠지지 않았는가?
'누적'인데 값을 계속 덮어쓰지 않았는가?
'각 항목마다 출력'인데 print가 반복 밖에 있지 않은가?
'마지막에 출력'인데 반복 중 계속 출력하고 있지 않은가?
```

## 코드 ↔ 실제 결과

```text
현재 반복에서 변수 값은 무엇인가?
조건식은 True인가 False인가?
함수 호출 결과는 무엇인가?
실제 자료형은 무엇인가?
값이 언제 처음 달라졌는가?
```

## 요구사항 ↔ 실제 결과

```text
경계값이 올바른 결과로 분류되는가?
제외 대상이 정말 제외되는가?
모든 항목이 필요한 횟수만큼 출력되는가?
합계와 개수가 정확한가?
평균의 분모가 올바른가?
```

> **좋은 디버깅은 코드를 오래 바라보는 것이 아니라, 세 가지 사이의 불일치를 좁혀 가는 과정입니다.**

# 5. 오류를 만나면 먼저 세 종류를 구분합니다

## ① 문법 오류

Python 문법 자체가 맞지 않아 정상적으로 실행되지 않습니다.

예:

```python
if score >= 80
    print("합격")
```

확인:

```text
콜론(:)
괄호
따옴표
문법적으로 올바른 들여쓰기
```

---

## ② 실행 오류

문법은 맞지만 실행 도중 프로그램이 멈춥니다.

대표적인 예:

```text
KeyError
TypeError
NameError
```

확인:

```text
Dictionary key가 실제로 존재하는가?
내가 예상한 자료형과 실제 자료형이 같은가?
변수 이름이 맞는가?
함수에 필요한 인수를 전달했는가?
```

---

## ③ 논리 오류

코드는 끝까지 실행되지만 결과가 요구사항과 다릅니다.

예:

```text
80점 이상이어야 하는데 80점이 탈락한다.
결제 완료 주문 수가 3이어야 하는데 1이 나온다.
학생 세 명을 출력해야 하는데 마지막 학생만 출력된다.
총액이 누적되어야 하는데 마지막 금액만 남는다.
함수 안에서 결과를 만들었지만 호출 결과는 None이다.
```

논리 오류에는 오류 메시지가 없을 수 있습니다.

따라서 반드시 다음이 필요합니다.

> **실행 전에 요구사항 기준 예상 결과를 만든다.**

# 6. 이번 실습에서 사용할 디버깅 10단계

Chapter 11의 기본 디버깅 루틴에 **재검증**을 추가합니다.

```text
1. 요구사항 기준 예상 결과를 적는다.
2. 실제 결과를 확인한다.
3. 예상과 실제가 처음 달라지는 위치를 찾는다.
4. 관련 변수 / 자료형 / 조건 결과를 관찰한다.
5. 원인 가설을 한 문장으로 적는다.
6. 가설과 관련된 한 부분만 수정한다.
7. 실패했던 같은 입력으로 다시 실행한다.
8. 경계값과 정상값도 다시 실행한다.
9. 모든 예상 결과와 실제 결과를 비교한다.
10. 원인과 수정 내용을 기록한다.
```

핵심 규칙:

```text
가설 하나
↓
수정 하나
↓
실패했던 테스트 재실행
↓
주변 테스트 재실행
↓
검증
```

한 입력만 맞았다고 끝내지 않습니다.

> **한 오류를 고친 뒤 다른 정상 동작이 깨지지 않았는지도 확인합니다.**

# 7. 디버깅할 때 사용할 관찰 도구

정답 코드를 찾기 전에 현재 프로그램 상태를 관찰합니다.

```text
현재 처리 중인 데이터 확인
현재 변수 값 확인
자료형 확인
조건의 True / False 확인
함수 반환값 확인
Dictionary key 확인
반복 전 / 반복 후 값 비교
```

대표적인 도구:

```python
print(...)
type(...)
```

`print()`는 디버깅할 때 **임시 센서**처럼 사용할 수 있습니다.

예:

```python
print("현재 주문:", order)
print("현재 count:", paid_count)
print("현재 total:", total_amount)
print("조건 결과:", amount >= 50000)
```

중요한 것은 많이 출력하는 것이 아닙니다.

```text
내 가설을 확인하기 위해 어떤 값이 필요한가?
```

이 질문에 답한 뒤 필요한 값만 관찰합니다.

# 8. 반복 문제는 반드시 반복 전 / 반복 중 / 반복 후로 나눕니다

많은 논리 오류는 문법보다 **실행 위치**에서 발생합니다.

```text
반복 전
→ 한 번만 준비할 값

반복 중
→ 현재 항목마다 실행할 일

반복 후
→ 모든 항목 처리가 끝난 뒤 한 번 실행할 일
```

예: 결제 주문 처리

```text
반복 전
- count 초기화
- total 초기화

반복 중
- 현재 주문 확인
- 처리 대상인지 판단
- count 누적
- total 누적
- 배송 결과 판단
- 현재 주문 결과 출력

반복 후
- 최종 count 출력
- 최종 total 출력
- 필요한 경우 평균 계산 및 출력
```

> **들여쓰기는 모양이 아니라 실행 범위와 시점을 표현합니다.**

# 9. 코드를 쓰기 전에 검증 계약을 만듭니다

Chapter 06에서는 실행 전에 최소한 하나의 **검증 계약**을 만듭니다.

검증 계약은 다음 질문에 대한 답입니다.

```text
어떤 입력을 넣었을 때
어떤 결과가 나와야 하는가?
```

예:

| 입력 | 확인하려는 요구사항 | 예상 결과 |
|---|---|---|
| score = 90 | 90 이상이면 A | A |

```python
]

paid_count = 0
total_amount = 0

for order in orders:
    if order["paid"]:
        paid_count = 1
        total_amount = order["amount"]

        if order["amount"] > 50000:
            delivery = "무료배송"
        else:
            delivery = "배송비 발생"

print(order["customer"], delivery)
print("결제 완료 주문 수:", paid_count)
print("총 주문 금액:", total_amount)
```

# 19. Final Challenge를 완료한 뒤 보는 기준 코드

> **주의: 문제 3의 설계·구현·검증을 끝내기 전에는 아래 코드를 보지 않습니다.**

아래 코드는 문제 3의 정답이 아닙니다.

Chapter 00부터 Chapter 12까지 배운 핵심 구조를 다른 도메인에서 복습하기 위한 **별도의 기준 코드**입니다.

```python
def get_delivery_result(amount):
    if amount >= 50000:
        return "무료배송"
    return "배송비 발생"


orders = [
    {"customer": "민수", "amount": 48000, "paid": True},
    {"customer": "지영", "amount": 72000, "paid": True},
    {"customer": "현우", "amount": 35000, "paid": False},
    {"customer": "서연", "amount": 91000, "paid": True}
]

paid_count = 0
total_amount = 0
highest_amount = None

for order in orders:
    if not order["paid"]:
        continue

    customer = order["customer"]
    amount = order["amount"]

    paid_count = paid_count + 1
    total_amount = total_amount + amount

    if highest_amount is None or amount > highest_amount:
        highest_amount = amount

    delivery = get_delivery_result(amount)
    print(customer, amount, delivery)

if paid_count > 0:
    average_amount = total_amount / paid_count
else:
    average_amount = 0

print("결제 완료 주문 수:", paid_count)
print("총 주문 금액:", total_amount)
print("평균 주문 금액:", average_amount)
print("최고 주문 금액:", highest_amount)
```

# 25. 이번 실습의 한 문장

> **처음 보는 문제를 해결한다는 것은 정답 코드를 떠올리는 것이 아니라, 자연어 요구사항을 구조로 바꾸고, 실행 전에 검증 기준을 만들고, 실제 결과와 비교하며, 오류를 단서로 원인을 좁힌 뒤 다른 입력까지 다시 검증하는 것입니다.**

이번 Python Foundation Bootcamp의 최종 흐름은 다음과 같습니다.

```text
문제를 읽는다
↓
자연어에서 구조를 찾는다
↓
데이터 / 반복 / 조건 / 처리 / 결과로 나눈다
↓
데이터를 설계한다
↓
필터링과 집계를 구분한다
↓
반복 전 / 중 / 후를 설계한다
↓
필요한 기능을 나눈다
↓
데이터 흐름을 연결한다
↓
수도코드를 작성한다
↓
검증 입력과 예상 결과를 만든다
↓
직접 구현한다
↓
실행한다
↓
예상과 실제를 비교한다
↓
처음 달라지는 위치를 찾는다
↓
원인을 추론한다
↓
한 부분만 수정한다
↓
실패했던 입력을 다시 확인한다
↓
경계값과 정상값도 다시 확인한다
↓
요구사항 전체를 최종 검증한다
```

> **문법을 먼저 떠올리는 사람에서, 문제의 구조를 먼저 찾고 자신의 코드가 그 구조를 정확하게 구현했는지 스스로 증명할 수 있는 사람으로 성장하는 것. 이것이 이번 Python Foundation Bootcamp의 최종 목표입니다.**
