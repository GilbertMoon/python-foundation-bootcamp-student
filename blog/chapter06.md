# 0. 이번 실습에서 가장 중요한 변화

앞선 실습에서는 주로 다음 단계까지 집중했습니다.

```text
요구사항 읽기
↓
데이터 / 반복 / 조건 / 처리 / 결과
↓
작은 기능으로 분해
↓
함수 입력 / 처리 / 결과
↓
수도코드
↓
Python 코드
```

이번에는 그 다음이 중요합니다.

```text
Python 코드
↓
실행 전 예상
↓
실행
↓
예상과 실제 비교
↓
차이가 있으면 원인 위치 좁히기
↓
가설 하나 세우기
↓
한 부분만 수정
↓
재실행
↓
최종 검증
```

즉 이번 Chapter에서는 **코드를 작성하는 것만으로 문제 해결이 끝나지 않습니다.**

> **예상 → 실행 → 비교 → 원인 추론 → 수정 → 검증**까지가 하나의 문제 해결 과정입니다.

# 2. 오류를 만나면 먼저 세 종류를 구분합니다

오류가 발생했다고 모두 같은 방식으로 접근하지 않습니다.

## ① 문법 오류

Python 문법 자체가 맞지 않아 실행 전에 멈춥니다.

확인할 것:

```text
콜론(:)이 빠졌는가?
괄호가 맞는가?
들여쓰기가 맞는가?
문자열 따옴표가 닫혔는가?
```

## ② 실행 오류

문법은 맞지만 실행 도중 문제가 발생합니다.

대표적으로 다음을 확인할 수 있습니다.

```text
Dictionary key가 실제로 존재하는가?
자료형이 예상과 같은가?
함수에 필요한 인수를 제대로 전달했는가?
```

## ③ 논리 오류

가장 주의해야 합니다.

코드는 정상 실행되지만 결과가 요구사항과 다릅니다.

예:

```text
80점 이상이어야 하는데 80점이 탈락한다.
합격자 수가 2명이어야 하는데 1명으로 나온다.
학생이 세 명인데 마지막 학생만 출력된다.
함수 안에서는 값이 만들어졌는데 밖에서는 None이 나온다.
```

논리 오류는 오류 메시지가 없기 때문에 **실행 전 예상 결과**가 매우 중요합니다.

# 3. 이번 실습에서 사용할 디버깅 9단계

오류를 만나면 아래 순서를 그대로 사용합니다.

```text
1. 예상 결과를 적는다.
2. 실제 결과를 확인한다.
3. 둘이 처음 달라지는 위치를 찾는다.
4. 관련 변수 값을 확인한다.
5. 예상한 자료형과 실제 자료형을 확인한다.
6. 원인 가설을 한 문장으로 적는다.
7. 한 부분만 수정한다.
8. 다시 실행한다.
9. 예상 결과와 다시 비교한다.
```

가장 중요한 규칙은 다음입니다.

> **가설 하나 → 수정 하나 → 재실행 → 검증**

한 번에 여러 곳을 고치면 무엇이 원인이었는지 알기 어려워집니다.

# 4. 디버깅할 때 사용할 수 있는 관찰 도구

대표적인 방법은 다음과 같습니다.

```text

조건 결과 확인

Dictionary의 key 확인
반복 전 / 반복 후 값 비교
```

`print()`는 이때 **임시 센서**처럼 사용할 수 있습니다.

`type()`은 화면에서 같은 값처럼 보여도 실제 자료형이 다른지 확인하는 데 사용할 수 있습니다.

중요한 것은 많이 출력하는 것이 아니라 **현재 가설을 확인하는 데 필요한 값만 관찰하는 것**입니다.

# 7. 요구사항 2 — 여러 주문을 처리하는 프로그램의 오류를 단계적으로 찾기

```text
1. 결제가 완료된 주문만 처리한다.
2. 결제 완료 주문의 개수를 센다.
3. 결제 완료 주문의 총 금액을 계산한다.
4. 50,000원 이상이면 무료배송으로 표시한다.
5. 50,000원 미만이면 배송비 발생으로 표시한다.
```

```python
orders = [
    {"customer": "민수", "amount": 48000, "paid": True},
    {"customer": "지영", "amount": 72000, "paid": True},
    {"customer": "현우", "amount": 35000, "paid": False},
    {"customer": "서연", "amount": 50000, "paid": True}
]

paid_count = 0
total_amount = 0

for order in orders:
    if order["paid"]:
        paid_count = 1
        total_amount = order["amount"]

        if order["amount"] > 50000:
            delivery = "무료배송"
        else:
            delivery = "배송비 발생"

print(order["customer"], delivery)
print("결제 완료 주문 수:", paid_count)
print("총 주문 금액:", total_amount)
```

# 13. 이번 과정 최종 기준 코드

아래 코드는 **실습 1·2·3의 정답 코드가 아닙니다.**

Chapter 00부터 Chapter 12까지 배운 핵심 구조를 한 번에 복습하기 위한 **최종 기준 코드**입니다.

복사해서 붙여 넣지 말고 직접 입력합니다.

```python
def get_delivery_result(amount):
    if amount >= 50000:
        return "무료배송"
    return "배송비 발생"


orders = [
    {"customer": "민수", "amount": 48000, "paid": True},
    {"customer": "지영", "amount": 72000, "paid": True},
    {"customer": "현우", "amount": 35000, "paid": False},
    {"customer": "서연", "amount": 91000, "paid": True}
]

paid_count = 0
total_amount = 0
highest_amount = None

for order in orders:
    if not order["paid"]:
        continue

    customer = order["customer"]
    amount = order["amount"]

    paid_count = paid_count + 1
    total_amount = total_amount + amount

    if highest_amount is None or amount > highest_amount:
        highest_amount = amount

    delivery = get_delivery_result(amount)
    print(customer, amount, delivery)

if paid_count > 0:
    average_amount = total_amount / paid_count
else:
    average_amount = 0

print("결제 완료 주문 수:", paid_count)
print("총 주문 금액:", total_amount)
print("평균 주문 금액:", average_amount)
print("최고 주문 금액:", highest_amount)
```

# 16. 최종 무자료 도전

과정 마지막에는 다음 순서로 진행합니다.

```text
1회차
기준 코드를 보면서 직접 입력
→ 각 줄을 말로 설명

2회차
코드를 닫고 기억으로 작성
→ 실행 전 예상 결과 작성
→ 실행
→ 틀린 부분 직접 디버깅

3회차
완전히 새 파일 또는 새 Notebook에서 무자료 작성
→ AI 사용 금지
→ 검색 금지
→ 예상 결과 작성
→ 실행
→ 오류가 있으면 디버깅 기록
→ 최종 검증
```

목표는 단순히 같은 코드를 외우는 것이 아닙니다.

> **코드를 잊어도 요구사항에서 다시 구조를 만들어낼 수 있어야 합니다.**

# 18. 이번 실습의 한 문장

> **처음 보는 문제를 해결한다는 것은 정답 코드를 떠올리는 것이 아니라, 문제를 구조로 바꾸고, 예상하고, 실행하고, 오류를 단서로 원인을 좁혀 끝까지 검증하는 것입니다.**

이번 과정의 최종 목표는 Python 문법을 더 많이 외우는 것이 아닙니다.

```text
문제를 읽는다
↓
구조를 찾는다
↓
작은 단계로 나눈다
↓
데이터를 설계한다
↓
반복과 조건을 찾는다
↓
필요한 값을 집계한다
↓
기능을 나눈다
↓
수도코드를 작성한다
↓
직접 구현한다
↓
실행 전에 예상한다
↓
실행한다
↓
차이를 찾는다
↓
원인을 추론한다
↓
한 부분만 수정한다
↓
다시 검증한다
```

> **문법을 먼저 떠올리는 사람에서, 문제의 구조를 먼저 찾고 스스로 검증할 수 있는 사람으로 성장하는 것. 이것이 이번 Python Foundation Bootcamp의 최종 목표입니다.**
