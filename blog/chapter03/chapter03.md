# Chapter 03. 조건은 문법이 아니라 판단 기준이다

> **이번 Chapter의 핵심은 `if` 문법을 외우는 것이 아닙니다.**  
> 문제 속에서 **무엇을 기준으로 판단해야 하는지**, 그리고 **정확히 어느 값에서 결과가 바뀌는지** 찾는 연습을 합니다.

---

## 조건문을 배웠는데도 왜 문제를 풀기 어려울까요?

Python 기초 수업에서 우리는 이미 다음과 같은 코드를 배웠습니다.

```python
if score >= 80:
    result = "합격"
else:
    result = "불합격"
```

문법 자체는 어렵지 않습니다.

그런데 실제 문제에서는 다음과 같은 부분에서 막히기 쉽습니다.

- 기준이 80점인지 81점인지 헷갈린다.
- `>`를 써야 하는지 `>=`를 써야 하는지 헷갈린다.
- 조건이 여러 개면 무엇을 먼저 검사해야 할지 모르겠다.
- 80점, 90점처럼 경계에 있는 값을 제대로 테스트하지 않는다.
- 코드는 실행되지만 결과가 이상한데 이유를 찾지 못한다.

이런 문제는 대부분 `if` 문법을 몰라서가 아닙니다.

**판단 기준을 정확하게 정의하지 않았기 때문입니다.**

이번 Chapter에서는 다음 질문을 반복합니다.

> **무엇을 판단하는가?**  
> **어떤 값을 기준으로 나누는가?**  
> **그 기준값 자체는 어느 쪽에 포함되는가?**

## 1. 이번에는 학생 성적 기준을 조금 확장합니다

0강부터 계속 사용한 학생 성적 예시를 그대로 이어갑니다.

이번에는 결과를 두 가지가 아니라 세 가지로 나눠 보겠습니다.

- 90점 이상: `우수`
- 80점 이상: `합격`
- 그 외: `보완 필요`

먼저 코드를 쓰지 말고 기준부터 읽어 봅시다.

```text
90점 이상 → 우수
80점 이상 → 합격
80점 미만 → 보완 필요
```

여기서 가장 먼저 해야 할 일은 Python 코드를 떠올리는 것이 아닙니다.

**점수 구간을 정확하게 나누는 것**입니다.

![점수 숫자선과 경계값](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter03/score-boundary-line.jpg)

숫자선으로 보면 훨씬 명확해집니다.

```text
79      80              89      90      91
│       │                │       │       │
보완     합격             합격     우수     우수
필요
```

즉 결과가 바뀌는 중요한 지점은 **80점과 90점**입니다.

이런 값을 **경계값(Boundary Value)**이라고 생각하면 됩니다.

## 2. 조건을 쓰기 전에 먼저 세 가지를 찾습니다

문제에서 조건을 발견하면 바로 `if`를 쓰지 마세요.

먼저 다음 세 가지를 찾습니다.

### ① 판단 대상

무엇을 보고 판단할까요?

이번 문제에서는:

```text
점수(score)
```

입니다.

### ② 기준값

어느 숫자를 기준으로 결과가 바뀔까요?

```text
80
90
```

입니다.

### ③ 결과

조건에 따라 어떤 결과가 만들어질까요?

```text
우수
합격
보완 필요
```

따라서 문제를 구조로 표현하면 다음과 같습니다.

```text
판단 대상: 점수
기준값: 90, 80
결과: 우수 / 합격 / 보완 필요
```

이 세 가지를 먼저 정리한 뒤 Python 코드로 옮깁니다.

## 3. `>`와 `>=`는 작은 차이처럼 보이지만 결과를 바꿉니다

다음 두 조건을 비교해 봅시다.

```python
score > 80
```

```python
score >= 80
```

둘은 비슷해 보이지만 의미가 다릅니다.

### `score > 80`

> 점수가 **80보다 큰가?**

80점은 포함되지 않습니다.

```text
79 → False
80 → False
81 → True
```

### `score >= 80`

> 점수가 **80보다 크거나 같은가?**

80점도 포함됩니다.

```text
79 → False
80 → True
81 → True
```

문제에서 **“80점 이상”**이라고 했다면 다음 조건이 정확합니다.

```python
score >= 80
```

## 4. 자주 사용하는 비교 연산자를 다시 확인합니다

이번 Chapter에서는 문법 자체를 새로 배우지 않지만, 조건을 정확하게 표현하기 위해 비교 연산자를 다시 정리합니다.

| 표현 | 의미 | 예시 |
|---|---|---|
| `>` | 크다 | `score > 80` |
| `>=` | 크거나 같다 | `score >= 80` |
| `<` | 작다 | `score < 80` |
| `<=` | 작거나 같다 | `score <= 80` |
| `==` | 같다 | `score == 80` |
| `!=` | 같지 않다 | `score != 80` |

여기서 중요한 것은 기호를 외우는 것이 아닙니다.

문제 문장을 정확하게 코드로 번역하는 것입니다.

예를 들어:

```text
90점 이상
```

은

```python
score >= 90
```

입니다.

```text
80점 미만
```

은

```python
score < 80
```

입니다.

## 5. 이제 판단 흐름을 사람의 말로 만들어 봅시다

이번 문제를 코드 없이 먼저 처리해 보겠습니다.

학생 한 명의 점수를 확인한 뒤 다음 순서로 판단합니다.

1. 점수가 90점 이상인가?
2. 그렇다면 `우수`
3. 아니라면 점수가 80점 이상인가?
4. 그렇다면 `합격`
5. 둘 다 아니라면 `보완 필요`

![조건 판단 흐름](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter03/condition-decision-flow.jpg)

이 흐름을 충분히 이해하면 Python 코드는 거의 그대로 번역할 수 있습니다.

```python
if score >= 90:
    result = "우수"
elif score >= 80:
    result = "합격"
else:
    result = "보완 필요"
```

여기서 `elif`는 이렇게 읽으면 됩니다.

> 앞의 조건은 아니었고, **그렇다면 이번 조건은 어떤가?**

## 6. `if / elif / else`는 위에서 아래로 검사합니다

다음 코드를 봅시다.

```python
if score >= 90:
    result = "우수"
elif score >= 80:
    result = "합격"
else:
    result = "보완 필요"
```

점수가 `91`이라면 어떻게 될까요?

### 첫 번째 조건

```python
91 >= 90
```

결과는 `True`입니다.

따라서:

```python
result = "우수"
```

가 실행됩니다.

그 순간 나머지 `elif`, `else`는 더 이상 검사하지 않습니다.

즉 `if / elif / else`는 **위에서 아래로 검사하다가 처음으로 True가 나온 곳에서 멈춥니다.**

이 점이 아주 중요합니다.

## 7. 조건의 순서를 바꾸면 왜 문제가 생길까요?

이번에는 일부러 잘못된 코드를 만들어 보겠습니다.

```python
if score >= 80:
    result = "합격"
elif score >= 90:
    result = "우수"
else:
    result = "보완 필요"
```

91점을 넣어 봅시다.

첫 번째 조건은:

```python
91 >= 80
```

`True`입니다.

따라서 바로:

```python
result = "합격"
```

이 됩니다.

뒤의 `score >= 90`은 확인조차 하지 않습니다.

![조건 순서 비교](https://raw.githubusercontent.com/GilbertMoon/python-foundation-bootcamp-student/main/images/chapter03/condition-order-compare.jpg)

따라서 조건이 겹칠 수 있을 때는 보통 **더 구체적이고 높은 기준부터 먼저 검사**해야 합니다.

이번 문제에서는:

```text
90 이상
↓
80 이상
↓
그 외
```

순서가 맞습니다.

## 8. 경계값을 반드시 테스트해야 합니다

조건문에서 가장 중요한 테스트 값은 아무 숫자나 고르는 것이 아닙니다.

**결과가 바뀌는 바로 근처의 값**을 골라야 합니다.

이번 문제에서는 다음 값이 특히 중요합니다.

```text
79
80
89
90
91
```

왜 이 값들일까요?

### 79

80 바로 아래입니다.

예상 결과:

```text
보완 필요
```

### 80

첫 번째 경계값입니다.

예상 결과:

```text
합격
```

### 89

90 바로 아래입니다.

예상 결과:

```text
합격
```

### 90

두 번째 경계값입니다.

예상 결과:

```text
우수
```

### 91

90보다 큰 값입니다.

예상 결과:

```text
우수
```

## 10. 전체 학생 예시에 적용해 봅시다

```python
students = [
    {"name": "민수", "score": 79},
    {"name": "지영", "score": 80},
    {"name": "현우", "score": 89},
    {"name": "수빈", "score": 90},
```

```python
for student in students:

    elif score >= 80:
        result = "합격"
    else:
        result = "보완 필요"

    print(name, score, result)
```


## 11. 중요한 것은 코드를 외우는 것이 아닙니다

다음 코드를 통째로 외우는 것이 이번 Chapter의 목표가 아닙니다.

```python
if score >= 90:
    result = "우수"
elif score >= 80:
    result = "합격"
else:
    result = "보완 필요"
```

더 중요한 것은 코드가 나오기 전에 다음 구조를 먼저 떠올리는 것입니다.

```text

↓
어떤 기준으로 나누지?
↓
경계값은 무엇이지?
↓
어떤 조건부터 검사해야 하지?
↓
각 결과는 무엇이지?
```

이 사고 과정이 먼저 나오면 Python 문법은 그 뒤를 따라옵니다.

## 16. 조건이 두 개 이상 동시에 필요한 경우도 있습니다

조금 더 현실적인 문제에서는 조건이 하나만 있지 않을 수 있습니다.

예를 들어:

> 점수가 80점 이상이고 출석률도 80% 이상인 학생만 최종 합격으로 처리한다.

이 문제에는 두 가지 판단 기준이 있습니다.

```text
점수 >= 80
출석률 >= 80
```

그리고 둘 다 만족해야 합니다.

Python에서는 다음처럼 표현할 수 있습니다.

```python
if score >= 80 and attendance >= 80:
    result = "최종 합격"
else:
    result = "보완 필요"
```

여기서도 먼저 문법을 보는 것이 아니라 문제를 구조로 봅니다.

```text
조건 1: 점수 기준
조건 2: 출석률 기준
관계: 둘 다 만족
```

## 17. `and`와 `or`도 문제 문장에서 먼저 찾습니다

### 둘 다 만족해야 한다

```text
점수 80 이상이고 출석률 80 이상
```

→ `and`

```python
score >= 80 and attendance >= 80
```

### 둘 중 하나만 만족해도 된다

```text
점수 90 이상이거나 프로젝트가 우수
```

→ `or`

```python
score >= 90 or project == "우수"
```

중요한 것은 `and`, `or`를 먼저 떠올리는 것이 아닙니다.

문제에서 관계를 먼저 읽는 것입니다.

## 19. 이번 수업에서 AI를 바로 사용하지 않는 이유

조건문은 AI가 코드를 만들어 주기 매우 쉬운 영역입니다.

예를 들어 다음과 같이 질문하면 AI는 바로 코드를 작성할 수 있습니다.

```text
90점 이상 우수, 80점 이상 합격, 나머지는 보완 필요인 Python 코드 작성해 줘.
```

하지만 이번 Bootcamp의 목적은 코드를 빨리 얻는 것이 아닙니다.

학생 스스로 다음을 판단할 수 있어야 합니다.

- 왜 90을 먼저 검사해야 하는가?
- 80은 어느 결과에 포함되는가?
- 어떤 값을 테스트해야 하는가?
- 결과가 이상하면 어떤 조건을 의심해야 하는가?

따라서 이번 수업에서도 순서는 다음과 같습니다.

```text
문제 읽기
↓
조건과 경계값 직접 정리
↓
예상 결과 작성
↓
직접 구현
↓
실행 및 비교
↓
필요하면 Python 공식 문서 확인
↓
마지막에 AI로 설명과 검증
```

> **AI에게 코드를 맡기기 전에, 판단 기준은 내가 먼저 정의합니다.**
